# CellPlanner：实验设计主流程与对象关系
日期：2026-11-02
状态：UX 主流程设计基线；核心数据关系采用可演进契约，已进入垂直原型验证（非发布版本）。

术语统一见项目根目录 [`CONTEXT.md`](../../CONTEXT.md)；本文较早的叫法按其中的旧术语映射理解，当前可运行 CLI 仍以根目录 `AGENT_API.md` 为准。

## 建议先定下来的产品结论

界面按“项目 → 实验 → 执行批次 →（可选）孔板 → 孔位”组织，不增加 Study 这一层。

- **项目**：一个长期课题，下面可以有多项实验，例如“氢能和琥珀酸干预 OA”。
- **实验**：一个可回答的问题，以及一份有版本的计划。例如“细胞实验中，氢处理是否改变某个预先指定的读数”。用户看到的主实体叫“实验”；底层现有 design 可继续作为这项实验的计划版本。
- **执行批次**：把某个计划版本实际做一次的记录，固定引用计划和 Protocol 版本。底层现有 run 可以保留，但界面用“执行批次”比“运行”清楚。批次不是 n，也不自动等于一次独立生物学重复。
- **孔板**：执行中实际使用的物理板，属于某个执行批次；一个批次可以没有板，也可以有多块板。
- **孔位**：板中的位置，关联实际样本/实验单位和它承载的处理或测量。

Protocol 是可复用、可版本化的方法文件，作为实验计划或执行批次的引用，不另加一层父子目录。计划阶段可以预览孔板布局；只有开始执行时才创建实际孔板记录。动物、试管、组织切片、患者队列等没有孔板时，不显示空板，也不要求虚构一个。

这与现有底层 project → design → run → plate → well 关系兼容。要改的是用户能理解的名称和设计到执行之间的结构化连接，不必为了改名重建数据库。

## 交互原则：先搭草案，再按需追问

上面的科学信息清单是**系统最终要能检查的内容**，不是新建页的一张长问卷。界面不应在开始时把八项内容一起摊给用户。

- **从一句话开始**：用户说“我想比较什么”，或选择复制已有实验/导入 Protocol。不要要求先选一堆科学术语。
- **先生成可见草案**：Agent 把用户描述、已有 Protocol 和本项目的记录映射到结构化字段，在同一个实验页面里更新组别矩阵、测量时间线和（需要时）孔板预览。每个抽取值能追到来源；没有来源的关键数字和条件保持“待确认”，不静默猜。
- **一次只问最影响下一步的一个问题**：系统按依赖顺序追问；例如先确认实验单位，再确认 n 属于独立样本还是技术孔，之后才计算孔位。每个问题旁说明它会改变什么，并给出适用选项、示例和“暂不确定”。不把所有问题一次发给用户。
- **边填边看结果**：回答后立即更新预览，让用户看到组数、样本数、采样日程或板图发生了什么变化；避免填完表后才看到一份长方案。
- **分层显示**：默认只展现当前决策所需字段；随机化细节、盲法阶段、统计假设等放在“偏差控制/分析”展开区，具体实验模式会用到时再显现。可跳过暂时未知项并保存草案。
- **只在真正开始执行时阻断**：草案可不完整；校验器逐项显示“缺什么、为什么重要、如何补”。只有当前模式下会影响执行安全或主要结论的必需项未确认时，才不能创建执行批次。不要用百分比或综合分数制造“差一点就完美”的错觉。
- **不单独建 Agent 草稿页面**：Agent 调用与人手编辑的是同一个实验对象、同一张设计画布。CLI 的解析/校验/预览是严格结构化工具；UI 负责把问题问得清楚、把答案可视化。

例如，用户只说“L929 做 CCK-8，三组，n=6，D1/D3/D7”时，系统先画出三组与三天的草图，然后只追问“每组的 6 是独立培养样本，还是同一培养批次里的技术孔？”用户选完后，才在需要时追问三天是否测同一孔。若用户暂时不知道，可保存草案并继续补其他部分，不必被一整页空字段卡住。

## 参考产品后收敛出的整体 UX

参考对象各取一项明确长处，不照搬完整信息架构：

| 参考 | 可借鉴的具体做法 | 在 CellPlanner 中的落点 |
|---|---|---|
| Todoist Quick Add | 先用一句话捕捉任务，项目、日期等细节可以随后补；详情不是起步门槛 | 新实验可先输入研究问题或导入旧记录，自动带入当前项目上下文；不强迫先填完字段 |
| Things | Today、Upcoming、Anytime、Someday 让“现在做”和“以后处理”分开 | 首页只呈现今天的实验任务与临近节点；未排期设计留在项目里，不伪装成今天待办 |
| NC3Rs Experimental Design Assistant | 用图形呈现实验关系，并在设计过程中给具体反馈；实验单位和测量关系不是自由文本注释 | 设计画布同时显示实验单位、分组、测量和时间点；校验跟着设计更新，指出具体冲突 |
| Minitab DOE Assistant | 实验可以分阶段；先回答当前阶段的问题，再依结果进入下一阶段 | 每个可回答的问题是一项实验；阶段门槛明确连接到后续实验，不把筛选、优化、验证塞进一个巨型表单 |
| Benchling | 可复用的 plate design 与一次实验中的实际 plate record 分开；实验记录按实验组织 | 计划期生成只读板图预览；执行时才生成实际孔板记录；Protocol 可复用且有版本 |
| Apple HIG、GOV.UK | 尽量预填可知信息、提供选择而非逼写长文本、动态校验；只在有帮助时分步提问 | 采用同页渐进完善：一次突出一个影响最大的疑问，回答后立即看到设计变化；相关项才放在一起 |

### 参考产品能力与 CellPlanner 的定位

NC3Rs EDA 已经能用图表示实验计划、给出设计 critique、提供统计方法建议，并支持随机化、盲法和样本量计算；Benchling Plate Annotator 也已提供自然语言生成孔位角色预览、应用或丢弃的流程（当前官方文档标注为 Preview）。因此，“有实验图”“会排板”或“能用自然语言标注孔位”都不宜单独作为差异点。[NC3Rs EDA](https://eda.nc3rs.org.uk/)；[Benchling Plate Annotator](https://help.benchling.com/hc/en-us/articles/40192825686669-Automate-plate-map-annotations)

CellPlanner 应借鉴它们的科学结构和预览确认方式，把重点放在轻量但连贯的工作流：研究问题→主要比较→样本/处理关系→可解释校验→计划与执行映射；不要求用户用拖拽图或聊天页学习一套新系统。
### 导航与对象关系

主导航建议保持四个入口：**今天、项目、日程、Protocol**。设置、导入和模板放在相应页面的操作菜单里，不再为 Agent 增加一套入口。

- **今天**只回答“我现在要做什么”：待执行步骤、今天到期的测量/观察、需要补记的偏差。
- **项目**承载课题；点进项目直接看到实验列表和阶段。实验是项目下的一级对象。
- **日程**汇总已排期的执行批次、时间点和提醒；尚未确定日期的实验不会被强行塞进日历。
- **Protocol**是可复用方法库。实验和执行批次引用具体版本，改 Protocol 不会悄悄改写历史记录。
- 主关系固定为**项目 → 实验 → 执行批次 →（可选）孔板 → 孔位**。不增加 Study 层；样本、实验单位、测量和 Protocol 作为明确关联对象，不再额外套目录。
- 全局“新建”入口按所在上下文工作：从项目内新建自动继承项目；从全局新建只多问“归属哪个项目”，而不是重复让用户填项目资料。

### 一次真实设计从开始到执行

1. **快速起步**：用户在项目里说“比较三种处理对 L929 活性的影响，做 CCK-8”，也可以复制旧实验或导入 Protocol。系统创建可保存的草案，并标明哪些字段来自原文、Protocol 或已有实验。
2. **先画已知部分**：先出现问题标题、已有组别和读数草图。未知的 n、剂量、时间点明确显示“待确认”，不让 Agent 猜数值，也不因缺项阻止保存。
3. **提出一个关键问题**：系统依据依赖关系挑当前最影响设计的疑问，例如“每组 n=6 指独立培养，还是同一培养样本的 6 个技术孔？”问题同时说明答案会改变什么。用户可选常用答案、填其他值或标记“暂不确定”。
4. **立刻更新画布**：答案写入后，组别矩阵和样本数量立即更新；如果读数时间点已知，才继续问“这些时间点会重复测同一批样本，还是每次取新的样本？”不相关的问题不出现。
5. **按实验类型给布局**：孔板实验出现板图；动物实验出现动物/笼位与随机化；影像队列出现受试者、MRI、标签来源和数据拆分。板图不是每项实验都必须有的固定步骤。
6. **检查可执行性**：用户可以随时看缺项。提示落到具体对象和字段，例如“每组需要 6 个独立培养单位，当前只有 4 个样本”；“D7 为破坏性检测，但未指定独立取样”；“这项读数没有单位”。草案仍可保存；只有创建执行批次时才按当前实验类型阻断安全关键缺项。
7. **创建执行批次**：确认计划版本和 Protocol 版本，生成实际任务清单与日程。若使用实体板，再创建实际孔板，并把计划映射到孔位；未使用板就不显示空白板。
8. **执行与收尾**：今天页按时间展示下一项要做的操作；用户记录读数、批次、偏差和未完成原因。结束时记录客观执行状态，若要改计划则新建版本，不把实际结果或临时偏差写回旧计划。

### 画布和引导如何配合

设计页应让人始终能回答“我们打算对什么单位做哪些处理、测什么、什么时候测、需要多少材料”：

- **顶部摘要**：研究问题 + 实验类型 + 计划版本；原始描述可展开，不用大段生成式总结占首屏。
- **主画布**：默认先显示组别矩阵；每行一个组，列出处理条件、对照角色和独立 n。用户能直接编辑单元格，也能用自然语言提出修改。
- **测量时间线**：每行一项 assay，标清材料、方法、单位、时间点，以及是否消耗样本；同一单位的重复测量与独立取样用不同连线/标记。
- **侧边/下方的“下一项”卡**：始终最多突出一个关键问题，给出选项、“其他”和“还不确定”；回答时说明影响组数、样本数、测量或执行安排中的哪一项。移动端把卡片放在画布之后，不挤成窄侧栏。
- **按需展开的细节**：随机化、盲法、纳排标准、样本量依据、分析方法按实验模式提供，收在“偏差控制与分析”等相关分组内；不把术语作为所有用户的首屏必答题。
- **条件面板**：只有进入铺板工具且布局信息足够时，才显示孔板预览与容量差额。设计页只列每组的位置数及其计数范围，不从 n 或时间点关系合成总孔位；实际坐标由铺板工具确认。
- **状态表达**：用“已确定 / 待确认 / 不适用（需说明）”表达信息状态；用文字和图形共同区分草案、可执行、执行中和已结束。不能只靠颜色、百分比或一个总分暗示科学设计质量。

### 系统承担的复杂度与 Agent 的边界

Agent 和人工用户操作同一份实验草案。Agent 的工作是把描述、导入内容和已有记录转成带来源的字段，指出矛盾，调用确定性工具计算输入关系足够的数量，并提出下一项具体问题；它不能替用户决定没有依据的 n、剂量、主要终点、排除规则或统计方案。

每个 CLI 工具仍需按动作定义封闭输入输出：导入先返回字段映射预览；validate/preview 只读；字段修改生成带路径的差异；明确的 create/revise 才写入。错误要指向对象、字段和原因，并区分“未知值”“不适用”“格式错误”“设计冲突”和“执行阻断”。操作回执明确版本、影响的派生数量、是否写入。这样 Agent 不需要一个独立草稿页，也不能绕过产品校验直接往数据库塞含糊文本。

### 问题顺序按依赖触发，不做固定长问卷

系统先把用户已经说过、导入或从已选 Protocol 中能确定的信息填好，再按“下一步计算或执行最依赖什么”挑一个问题。已知答案不再重问；与当前实验类型无关的字段不出现；暂时不影响草案的内容留到后面。每个问题卡都同时显示：为什么问、会改变画布哪一处、可选答案、其他、暂不确定。

| 实验路径 | 第一项只在缺失时追问 | 回答后立刻可视化什么 | 仅在后续依赖出现时再问 |
|---|---|---|---|
| L929 CCK-8，用户已说三组、n=6、D1/D3/D7 | “这里的 n=6 是 6 次独立培养，还是 6 个技术孔？” | 每组独立培养数与技术孔数；不把技术孔计成独立 n | 如果方法/Protocol 没说明，再问各时间点是否同一批样本重复测量；处理条件、剂量、单位只对缺失的组/读数提问 |
| 划痕成像，用户已说 0/12/24 h | “这些时间点要追踪同一孔、同一视野吗？” | 同孔/同视野的配对连线，或独立取样提示 | 需要生成执行清单时再问每组孔数、每孔视野数；只有开始排板时才展开孔位 |
| 生物膜多 assay | “这些检测分别用独立样本，还是从同一批生物膜分样？” | 每个 assay 的样本来源和所需载体，显示分样冲突或数量 | 仅对实际用板的 assay 追问板型/孔位；玻片、培养皿等各用自己的载体，不强求共用孔板 |
| 动物分组 | “处理分配到单只动物，还是整笼一起处理？” | 正确的随机化单位、每组独立单位数和所需动物/笼数量 | 执行准备时再确认随机分配、盲法阶段、纳排标准和样本量依据；草案首屏不把它们全部展开 |
| MRI → H/I 转录亚型 | “H/I 标签对应患者，还是患者的某份组织标本？” | 患者—MRI—标本—标签的关联图和可用样本数 | 建开发/验证集时才问按患者还是中心分组，避免同一患者数据泄漏；不创建孔板 |
| 分阶段 OA 实验 | “当前这项要筛选因素、找范围，还是确认一个既定条件？” | 当前阶段的因素/水平和设计类型提示 | 只有前后阶段相依时再定义继续/停止门槛；不要求用户预填尚未开展阶段的所有参数 |

若一个缺失字段会影响多个派生结果，优先问它；若只是记录完整性而不会影响当前可视化或安全执行，则先列入待补项。用户标记“暂不确定”后，系统保留空值和影响说明，不用默认值伪装成科学事实。

### 页面布局要同时适合桌面与手机

| 区域 | 桌面 | 手机 |
|---|---|---|
| 全局导航 | 左侧窄导航：今天、项目、日程、Protocol；内容区宽屏 | 底部或顶部紧凑导航；当前页只显示主内容 |
| 实验页头 | 项目路径、实验名、草案/版本状态；保存状态清楚可见 | 项目名收进面包屑，实验名和状态保留 |
| 设计画布 | 组别矩阵为主，测量时间线紧随其后；下一项问题在右侧固定宽度卡片 | 先显示摘要与下一项问题，再显示组别卡；宽表转为可读的组卡，不做横向滚动 |
| 孔板 | 条件满足时以网格显示，并配组别/测量图例 | 保留可读的行列标签；先给分组清单，用户主动进入孔位网格 |
| 操作 | 保存草案为次操作；校验并开始执行为明确主操作，旁边显示阻断原因 | 底部保留保存与继续入口；不把关键确认藏进悬浮菜单 |

画布不要同时展示所有实验字段。可视化中直接编辑常见条件；低频或专业字段收在与任务相邻的折叠面板里。组别、测量、样本和载体切换使用稳定的标签，不依赖颜色单独传递含义；每次改动都能看见样本数、时间安排或载体需求的变化。


### V1 设计决策（按真实记录走查后收敛）

1. **对象层级固定**：项目 → 实验（一项可回答的问题）→ 执行批次 → 可选物理容器/孔位；不新增 Study。Protocol 独立版本化并被实验/执行批次引用。
2. **一个问题可有多项检测**：同一比较下的 CCK-8、成像、CFU、组织学等是不同检测面板，各自关联样本、时间、对照和载体；研究问题或决策阶段不同才拆成新实验。
3. **旧记录先辨用途**：导入必须区分复制为新计划、重建历史计划、补记执行批次。计划、实际执行、结果和偏差绝不自动混成同一对象。
4. **默认画布保持简单**：问题/比较、组别、主要读数、样本/孔位现状、当前最重要的一项待确认；其它未知项集中显示，可直接编辑或批量填写。用户不必学习内部字段名。
5. **检测面板各有自己的关系**：时间锚点、样本复用/终末取样、适用对照与实际容器都按检测面板设置，不能只用一组全局 timepoints 或全局 controls。
6. **处理因素与操作设置分开**：药物/材料剂量是处理因素；接种体积、仪器参数等是操作设置；培养日/材料批次是区组或来源变量。所有数值保留原单位和来源，系统可推导换算但不得用换算结果覆盖原始输入。
7. **n 不由孔数代替**：分别显示处理分配数、材料来源数、独立实验批次数、样本/分样数、技术读数数和容器/孔位数；按主要比较保留 n 的依据，不设通用默认值。
8. **计划和实际分开**：计划预览不创建实际孔板；开始执行时固定计划与 Protocol 版本，再记录真实容器、时间、样本去向、读数和偏差。
9. **引擎与 Agent 各守边界**：引擎负责确定性计算与明确规则检查；Agent 只提出有来源的字段修改和差异预览；改变 n、剂量、主要终点等科学决定必须用户确认。
10. **实现顺序由真实走查决定**：先导入预览/来源状态，再实现检测面板与变量角色，接着做数量、单位、容量、时间/样本关系校验，最后接执行批次；复杂统计和 MRI 预测专用流程另行扩展。

真实记录走查和逐项 Gap 见[CellPlanner V1：实验设计流程走查与 Gap 清单](2026-11-02-cellplanner-design-flow-walkthrough.md)。这份规格定义产品逻辑，不代表代码或自动导入功能已经实现。
## 科学语义模型：后台完整，前台只露出当前要做的决定

底层要比界面严谨，但不要把底层实体名变成用户的必填词汇。原则是：**关系始终有位置存，只有它影响当前计算、比较或执行时才显出来。**

| 要表达的关系 | 内部保留什么 | 用户何时看到 |
|---|---|---|
| 要回答什么 | 研究问题、主要结局、预定比较（哪些组/条件互相比）及探索/验证意图 | 默认显示一句问题和一条“主要比较”；若有多个因素且存在不同科学问题，再询问最想判断哪一个 |
| 材料从哪来、处理分给谁 | 可选的来源 ID、独立分配处理的单位 ID、样本 ID、分样/子样父 ID | 只有“n 是谁”、样本分配或配对关系不清楚时，才展开来源→处理单位→样本关系 |
| 希望得到什么读数、怎样测、实际得到什么 | 目标读数、测量方法/Protocol、实际原始观察值及其派生计算与版本 | 计划页呈现为一行“读什么 / 怎么测 / 何时测”；执行后才出现原始值、校正值和换算过程 |
| 样本何时测、能否继续用 | 相对时间锚点、间隔/允许窗口、样本使用策略：可重复测量、终末取样、分样或依条件复用 | 只有日程需要落地或多项检测共用样本时，才问“D3 从哪个事件算”和“测后样本怎么处理” |
| 哪些安排影响结论 | 对照角色、批次/区组、随机化和盲法、适用的排除规则 | 只显示与已选方法或当前安排相关的核对项；不是所有实验都强制出现同一套对照或随机化字段 |
| 实际放在哪里 | 孔板、培养皿、玻片、动物笼位等物理载体，与样本、处理和测量的引用关系 | 仅在设计确实需要某种载体时显示布局；不把孔板当成样本或实验单位的同义词 |

### 内部字段词表：对象可计算，术语不变成用户门槛

以下是供数据模型、CLI 和确定性引擎共用的概念字段建议；并非每种实验都要创建每类对象，只有形成了相应关系才生成 ID。

| 建议字段/关系 | 精确定义 | 前台默认说法 |
|---|---|---|
| planned_comparisons[] | 要比较的组/因素条件、目标 outcome、主/次要及探索/验证意图；不内含统计检验 | “主要比较” |
| biological_source_id | 生物材料来源，如供者、动物、细胞来源/批次 | “材料来源” |
| allocation_unit_id | 实际接受处理分配的单位；例如个体、独立培养、独立分配的孔或样本 | “处理分给谁” |
| n_basis_id | 对某个主要比较/结局计数 n 的独立推断层级；它可能与分配单位相同，也可能需要考虑共同来源、配对或聚类 | “每组 n 按什么算” |
| sample_id / parent_sample_id | 实际检测材料与它的分样/派生来源；不等同来源 ID 或分配单位 ID | “样本 / 从哪份样本分出来” |
| group_id / factor_assignments | 稳定组 ID 与其处理因子/水平；用于比较、随机分配和板位映射 | “组别 / 处理条件” |
| variable_role / value / unit | 标明 treatment、setup、blocking 或 time 等用途；保存原值、单位和来源 | “处理条件 / 操作设置 / 批次 / 时间” |
| outcome_id / assay_plan_id | 目标结果是什么，与如何获取该结果的过程分别建模；一个测量过程可产生多个 outcome | “读数 / 检测方法” |
| observation_id / transform_id + version | 实际原始观察值，与校正/归一化/汇总后的派生值和计算版本分开 | “原始读数 / 处理后的结果” |
| anchor_event_id + offset + window | 相对起始事件、时间偏移和允许范围；执行开始后再换算日历时间 | “处理后第 3 天（允许窗口）” |
| `timepoint_relation` + `source_relation` + evidence | 分开记录跨时间点测量对象与跨检测来源/复用关系；旧 `sample_use_policy` 只兼容输入且不能解释含糊的 `same_sample_repeated` | “同一实验单位多次测量 / 同一份实体样本多次测量 / 各时间点独立取样 / 待确认” |
| control_role / block_id / randomization_plan_id | 对照作用、区组归属和随机分配方案；按适用性建立 | “对照用途 / 批次平衡 / 随机安排” |
| assay_control_scope | 明确每个对照适用哪些检测、读数和处理条件，不默认对全实验生效 | “这项检测的对照” |
| container_id / well_id | 实际容器及孔位；物理位置不是样本、来源或 n 的同义词 | “板 / 孔位 / 玻片” |

独立分配单位数、独特材料来源数、样本/分样数、技术读数数和物理孔位数要分别计算。多个分配单位来自同一来源时，source ID 用于保留配对/区组关系，不能把每组单位数相加后当成独立来源数。反过来，单位若确实可独立分配和分析，也不能仅因共享来源名称就机械合并。具体推断取决于分配方式、依赖结构和目标比较，不由数据库对象名称决定。
### 比较目标不是组别表的隐含副产品

因素和组别说明“做了哪些条件”，但不一定说明“要比较什么”。计划中要有可追溯的主要比较，并可选次要比较；它关联目标读数和相应的组/因素条件。系统不据此自动挑统计检验，也不把对照组名当作研究者意图。

在 2×2 因素设计中，若用户的目标尚不明确，等组别矩阵出现后再用普通语言给选择，例如“看 H₂ 的整体作用”“看 SA 的整体作用”“看两者是否有交互”“只比较联合处理与对照”“暂不确定”。简单的两组比较不必再问一遍；系统可以把明确的比较显示成可编辑标签。没有完整组合时，只有在用户选择了需要完整因子组合的目标后，才提示缺了哪一格，不自动补组。

### n 跟“独立分配处理的单位”走，不按物件类型猜

系统必须区分材料来源、处理分配单位、被测样本/分样、实际读数以及物理容器。这些关系不是一条固定的“供者→样本→孔”流水线：一个来源可以拆成多个相关样本；同一处理单位可以有多个技术读数；一个样本也可能产生多个读数。只在实际需要时创建子样本关系，不先建设完整库存系统。

软件不能只靠每组的 independent_n 和 technical_replicates 两个数字表达样本层级。它要分别保留：处理实际分给哪个 allocation_unit、这些单位来自哪个 biological_source、每个主要比较/结局按哪个 n_basis 计数，以及单位产生了哪些 sample 和 observation。n_basis 需要依据预定比较与依赖结构明确；同一供者分样进入多个组时要保留配对/区组关系，不能把各组样本行相加就报告为独立供者数。一个孔可以是独立分配单位，但不因此自动成为所有分析的独立 n；反之也不能按物件类型一律排除孔。ARRIVE 将实验单位联系到独立接受干预且不互相影响的生物实体，并警告将子样本/重复测量当作独立单位会造成伪重复。[ARRIVE：实验单位说明](https://arriveguidelines.org/arrive-guidelines/study-design/1b/explanation)

### 读数、方法和实际数据分开保存

一个计划读数可以叫“相对细胞活力”，测量方法是 CCK-8；执行时产生原始 OD，之后可能做空白校正、对照归一化，得到派生结果。系统应分别保留目标读数、方法/Protocol、原始观察和派生计算（公式及版本），这样可重算，也能核对空白或干扰背景；界面默认仍只显示一行读数，不要求用户学习 endpoint、assay、observation 这些内部术语。NC3Rs EDA 同样将测量过程、结果指标和后续数据变换分开表达。[NC3Rs：Measurement 与 outcome measures](https://eda.nc3rs.org.uk/experimental-design-measurement)

样本使用不能只有“破坏性/非破坏性”布尔值。计划应能表达：测一次后可否重复测、是否终末取样、是否分样、或是否只有在指定 Protocol/条件下才能继续用。兼容性要来自已选 Protocol、实验室已验证规则或用户确认。Dojindo 的 CCK-8 说明指出其细胞毒性较低，完成后在相应条件下仍可用于其他检测；同时也说明影响脱氢酶活性的条件或还原剂可能干扰读数。它不能被系统泛化成“同一孔必定适合 D1/D3/D7 重复测量”，也不能固定判为终末检测。[Dojindo：CCK-8 技术手册](https://www.dojindo.com/manual/CK04/)

### 时间、对照和批次作为可计算的关系

“D3”只有在锚点明确后才能排入日程：例如处理开始后第 3 天。计划保存锚点事件、相对偏移和允许窗口；执行时用实际事件时间推导日历时间。锚点尚未确定时保留相对时间，不捏造日期。测量时间、频率和重复方式会影响设计和分析，因此只在它们改变安排时追问。[NC3Rs：测量时间和重复测量](https://eda.nc3rs.org.uk/experimental-design-measurement)

对照用结构化角色表达，建议则依赖所选方法和材料。例如空白、未处理/载体对照、阳性对照、材料背景/检测干扰对照可以在适用时出现；软件不能把某一套对照设为所有实验的统一必填项。提示需说明触发依据，让研究者确认、修改或标为不适用。

培养日、批次、操作者或板位只有在记录了它们与组别的实际分配关系时，才能检查混杂。若各处理组完全按不同日期执行，系统可指出处理与日期重合，并展示依据；若信息不全，只能说“目前无法检查批次平衡”，不能断言存在混杂。真正区组设计需在区组内安排处理条件；其余无法控制的影响再通过合适的随机化降低。软件可做确定性结构检查，但复杂设计是否可识别、是否适合目标仍需专业判断。[NIST：随机区组设计](https://www.itl.nist.gov/div898/handbook/pri/section3/pri332.htm)

### 三种信息密度、三种编辑方式

- **默认层：几秒看懂**——研究问题、主要比较、组别与可确认的 n、主要读数/时间、最重要的一个未决点。
- **当前决策层：点到哪项就展开哪项**——选中组别看来源与分配单位；选中读数看方法、样本和时间；样本存在分支或复用时，才出现样本流向图。
- **专业层：需要时才开**——区组、随机化、盲法、排除规则、样本量依据、原始数据处理和分析计划。可以从这里直接编辑，不强迫新手走一遍专业向导。
- **三种等价编辑方式**——Agent 一次提出一个关键问题、用户直接改画布/表格、熟练用户批量粘贴或导入。单题是默认引导方式，不是强制串行锁；没有关键问题时，问题卡收起或显示有证据的检查结果。

Agent 可以把文字转成建议字段、展开组别、计算物料和任务、排板，并先显示差异。它不能把建议当作事实，不能替用户定 n、主要比较或关键参数。确定性引擎负责数量、映射、容量、时间依赖和明确定义规则的兼容性检查；每条诊断显示触发依据、影响和下一步。

### 建议、提醒和执行阻断要分级

- **阻断**：当前执行无法安全或一致地生成，例如必需分配关系缺失、孔位超容量、样本同时被安排到明确不兼容的终末步骤。只阻止创建执行批次，不妨碍保存草案。
- **需确认**：结构提示可能影响结论，但不应被当成既成错误，例如 n 的单位不清、样本复用条件未说明、目标比较与组别结构不一致。
- **建议**：方法相关的可选改进，例如可能需要的背景对照、随机化、盲法或备份量。显示为什么建议、基于哪个 Protocol/规则；不自动套用，也不以“缺少建议项”冒充实验无效。

每条建议区分“用户确认”“导入/Protocol 来源”“程序推导”“Agent 建议”。派生结果可自动更新预览；改变科学决定的修改要先给差异和影响，再由研究者确认写入。

### 生命周期分开，避免“可执行”成为另一种状态

计划版本用草案、已确认、已被新版本取代表示；“当前是否可以创建执行批次”由校验器动态计算，不存成与计划生命周期并列的状态。执行批次另有待执行、执行中、已完成、已中止等状态，并固定引用计划与 Protocol 版本。计划修订不会悄悄改写已经开始的执行批次。
## 设计中最终要能回答的事（按需显现）

字段完整性是系统的责任，不是首屏问卷。内部至少能表达以下内容，用户只在当前缺少且会改变决定时回答：

1. **想比较什么，主要看什么读数？** 先收研究者自己的问题；组别明确后再呈现主要比较。若比较目标还不明确，给相关选项和“暂不确定”。
2. **n 对应什么独立分配单位？** 只在 n、技术重复、样本来源或配对关系模糊时问清。系统先展示解释性选项，不要求用户从实验单位术语学起。
3. **有哪些处理条件，如何组成组？** 将因素、水平、组和对照角色结构化；不默默补齐用户未计划的因子组合。
4. **希望得到什么读数，使用哪种方法？** 计划读数、方法、材料、单位和 Protocol 版本可分别追踪；一个实验可以有多项读数。
5. **什么时候测、样本还能否用于下一步？** 只有日程/样本流向依赖它时，才确认时间锚点、重复测量/终末取样/分样条件。
6. **实际安排能否容纳？** 依据明确的位置范围和实际布局映射计算容量；不能从 n 或时间点关系推断唯一孔位。只有布局阶段才细化到板型和孔位。
7. **哪些偏差控制适用？** 视实验模式和已知风险检查批次平衡、随机化、盲法、对照和纳排；不适用或未实施可如实记录原因。
8. **哪些值仍未知，来源是什么？** 每个关键值有确定/待确认/不适用状态和来源。不得把推断或 Agent 建议写成用户确认的事实。


## 结果画布：始终能看到实验目前长什么样

默认页面不是“下一步、下一步”的多页问卷，而是一个能持续看到结果的画布：

- **上方：这次实验要回答的问题**。保留用户原话，可由用户或 Agent 改写；旁边显示当前实验类型和计划版本。
- **主画布：组别矩阵与主要比较**。一行一个组，显示条件、对照角色及已能确认的独立单位数；主要比较以紧凑标签显示，复杂分配时才展开来源/样本关系。
- **测量时间线**。每行一个用户可读的目标读数，展开后显示方法、样本、锚点事件和时间窗口；终末取样、重复测量与分样分别标记。
- **当前决策卡**。只有确有影响设计的未决项时才突出一个问题，并解释影响；无关键问题时显示检查结果或收起，熟练用户可直接编辑/批量填表。
- **孔板与样本流向是按需面板**。使用多孔板时显示可计算板图；存在分样、跨 assay 复用或多层来源时再显示样本流向图。
- **执行状态**。计划版本是草案/已冻结/被取代；可否执行是即时检查结果。执行批次另有自身状态，并保留实际板图、样本、原始读数和偏差。

用户可逐题回答、直接改矩阵，或批量粘贴；也能用自然语言提出修改。Agent 将其转成字段差异与影响预览，科学决定经用户确认后写入新版本；人与 Agent 共用同一对象，不建专属草稿页。

不同实验类型通过条件面板切换，而不是强塞一个全能表单：细胞实验展示孔位和测量日程；动物实验展示动物/笼位和偏差控制；队列或 MRI 预测任务展示受试者/影像/标签与数据集分割；多方法实验展示 assay 卡片及各自载体。核心页面都能用同一条关系链，只有执行布局随类型变化。


## 不同实验类型使用同一条主链，显示不同的执行布局

- **细胞/孔板实验**：同一培养物上的技术孔、独立培养、同孔多时间点分别记录。若读数会破坏样本，就为该时间点生成独立样本分配；不能把 assay 名称塞进一段 protocol 文字后假设板数已经算对。
- **划痕/成像**：在同一实验单位下保存孔位、视野/图像 ID 与时间点；后续时间点要能回到同一视野。不同照片没有可配对 ID 时应明确显示无法做视野级配对。
- **生物膜多方法检测**：CV、CFU、活/死染色、CLSM、SEM 等可以属于同一科学问题，但各自单独指定样本、载体、时间、方法和是否消耗样本；玻片、培养板、培养皿都作为执行批次下的实际容器。
- **动物实验**：不要求孔板。增加 ARRIVE 相关的实验单位、组别、每组 n 与依据、随机分配、盲法、纳排、主要结局和统计方法字段。
- **影像预测分型（如肩袖 MRI → H/I 转录亚型）**：不要求孔板。单位是患者/标本的明确关联；记录入排标准、MRI 采集与预测时点、转录亚型结局定义、缺失数据、开发/验证数据如何分开及是否按患者/中心避免泄漏。TRIPOD+AI 是预测模型研究的报告规范，可转成完整性检查；它不会替研究者选模型或证明样本量够用。
- **分阶段材料/动物研究**：同一个 Project 下按每个可回答的问题拆成独立 Experiment；前一阶段的停止/继续条件写成明确字段。不同阶段不塞进一个巨型实验，也不为每一阶段再套一个 Study 目录。

## 对照现有 CLI 后发现的实现缺口

现有接口已有可保留的基础：design 含实验单位、组别、独立 n、技术重复、时间点、主要终点/方法/单位；run 创建时固定当前 design 版本和可选 Protocol 版本；plate 属于 run，well 属于 plate。见 AGENT_API.md 的设计语义，以及 src/cli.rs 中 run.create、plate.create、well.set 的输入定义。

还缺几项关键连接：

- design 中的 experimental_unit 是自由文本；group_specs 有条件文本，但没有可校验的因素/水平/组组合表。
- timepoints 是独立字符串数组，primary_endpoint / endpoint_method / endpoint_unit 只表达一项主要读数；不能表示多个 assay 各自对应什么样本、时间、方法、单位和取样方式。
- well.set 目前主要写 group_label、sample_id、note；没有稳定 group ID、assay/measurement ID、时间点和技术重复类型的完整映射。
- plate.create 只创建空布局；还没有从实验计划生成只读预览、检查分组 n 与孔位映射一致性、或报告超出板容量的校验契约。

建议不一次性重做整套系统。先加结构化 factors/groups 与 measurements，再加只读 design.validate / design.preview；先让“计划算得出来、孔板对得上、缺项说得清”成立，然后才扩展导入和执行数据字段。

## 数据契约冻结边界

UX 主流程可以冻结，底层 schema 只冻结已经被真实案例验证的关系；不为“将来可能有用”一次性建出完整样本库或本体。

- 用户仍只看项目、实验和执行批次。`SampleAllocation` 作为内部关联，表达某组的计划材料如何进入某项检测；列表、组别和数量可直接看懂，只有发生分样/顺序复用时才展开来源关系。
- 设计阶段只保存数量、分配规则和逻辑计划槽位，不创建看似真实的 sample ID、well ID 或实验结果。开始执行后才实例化真实样本和容器，并记录实际映射。
- Protocol 引用属于具体 assay。Run 创建时冻结其设计版本和 assay→Protocol 精确版本清单；后续编辑 Protocol 或设计不能改写已有 Run。
- `SampleAllocation` 的来源最终必须允许链接到真实来源材料（如培养物、组织样本或 aliquot），也可链接到先前 assay 的处理产物；当源对象不是 assay 时，不能为了满足字段而伪造 `source_assay_id`。现有原型只实现 assay 来源引用，来源为起始培养物时明确保留 unknown。
- 同一设计可创建多轮 Run。轮次编号用于导航；`repeat_of_run_id` 和 `repeat_relationship` 说明轮次来源。Run 数量绝不自动等同独立 n。
- 导入保留原文证据、文档定位和多条未决解释。用户确认后追加解释，不覆盖原始记录。定位字段帮助回到原文；不加一个容易被误当作科学正确概率的置信度分数。
- 执行中的改动需区分新设计版本、执行偏差、临时追加操作与原始数据更正；原型先确保不覆盖事实，完整事件审计契约留待执行流验证后定型。

界面不要求用户认识 `SampleAllocation`、`allocation_unit_id` 等内部词。默认显示“每组要用多少个样本/容器位”；当检测间样本需要拆分或复用时，才展开“从哪项检测取得”。

## CLI / Agent 输入输出边界

围绕同一份版本化实验对象，提供窄而明确的工具契约；Agent 负责理解与提议，确定性引擎负责计算和校验，UI 与 CLI 使用同一规则。

- design.preview 与 design.validate：只读。返回字段来源/待确认项、主要比较，并按比较列出处理分配数、唯一来源数、n_basis、样本与观察数；同时给样本流向/载体布局、时间依赖、诊断级别及依据；不写数据库、不替用户补值。
- design.propose_patch：只读提案，输入 design_id、expected_version 和带字段路径的 changes；返回 field_diff、受影响对象、重新计算的需求、新诊断与 requires_confirmation。Agent 不发送整份对象覆盖，未知字段按封闭 schema 报错。
- design.commit_patch：写入新计划版本；只接受针对提案和预期版本的明确提交。科学决定类差异要研究者确认；安全可逆的派生布局可按产品授权生成，仍留下来源和回滚路径。版本冲突拒绝覆盖新修改。
- import.preview：只读，返回原内容到规范字段的映射、来源、未知字段和冲突；用户/Agent 确认后才能写入。
- run.create：写入执行批次，固定引用已选计划与 Protocol 版本，并返回其 ID；可从已确认设计生成任务、相对日程和样本/容器清单。
- plate.create / well.assign：仅在实际使用实体孔板时创建记录；孔位引用稳定的组、样本、测量和处理分配 ID，而非仅靠自由文本组名。

每个回执有稳定对象 ID、版本、字段级错误路径和写入状态。来源标为用户确认、导入/Protocol、程序推导或 Agent 建议。输出不把原始异常、任意自由文本或未经确认的模型建议伪装成结构化事实。


## 第一轮验收路径：看系统是否真懂设计关系

1. **L929 CCK-8**：分别测试“每组 n=6，但单位未说明”“每组 6 个独立培养单位”“每组 6 个技术孔”三种输入。只有在用户确认每组 6 个技术孔且每个时间点独立取样时，才推导 3 组 × 6 孔 × 3 时间点 = 54 个实验孔；数字必须标清假设，不由输入中的 n=6 自动猜出。实际对照和背景孔由所选 Protocol/材料干扰风险触发，不能一刀切。
2. **划痕成像**：每组 3 孔、每孔 3 视野、0/12/24 h 时，可推导 81 张图像计划，但 n 仍按实际处理分配单位计算；相同视野的时间点图像需能配对。缺少视野对应时，提示无法做视野级配对。
3. **生物膜多 assay**：验证样本分样/父子关系、同一材料能否服务多个步骤、CFU/染色/显微镜不同载体如何生成；只有在 Protocol/验证规则明确不兼容时才阻断。
4. **H₂ × 琥珀酸 OA**：能显式表达 H₂ 主效应、SA 主效应、交互作用或联合处理对照等不同目标；比较目标不明确时提供选择。非完整 2×2 组合不得被静默补齐。
5. **动物实验**：分别测试个体分配、整笼分配与同一动物不同部位等情况，确保处理分配单位、来源和测量单位可区分；没有孔板也能预览。
6. **MRI → H/I**：关联患者、影像、组织标本和亚型标签；验证同一患者多份材料/多次影像的关系，以及训练/验证按患者或中心拆分的提示；不生成孔板对象。
7. **批次与日程**：若处理组与培养日完全重合，结构信息足够时给出“可能无法区分处理效应与日期效应”的依据与重新平衡建议；信息不足时提示无法检查。D3 必须有明确的起始事件，或保持相对时间不生成确定日历日期。
