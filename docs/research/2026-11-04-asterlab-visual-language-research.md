# AsterLab 视觉语言与图标方案研究

- 日期：2026-11-04
- 状态：研究候选，待在现有界面上做静态/交互验证；不是已批准的视觉规范，也不是用户测试结论。
- 基线：仓库 HEAD bf1f0e9f320bd7704e468354b3eb19b26156747e；本轮仅读源码与官方资料，没有改 UI、启动应用或运行测试。

## 结论

采用分层的视觉方案，不让一种图标或插画承担所有信息：

1. **通用界面图标**：全产品只选一套开源线性图标，服务导航、操作和状态。
2. **实验关系图**：用项目数据生成的 SVG/HTML，表达组、检测、时间、样本去向和状态；不拿装饰图代替科学关系。
3. **操作示意图**：对加样、分样、孵育等确实能因此更好理解的步骤，使用少量可联动的矢量示意；孔位仍以准确的俯视板图为准。
4. **产品角色**：若核心流程验证后仍有需要，再做一个原创、低干扰的 Lab Buddy；它只表达助手状态，不传递科学结果。

澪在交叉审阅中建议将 **Tabler Icons** 作为当前优先候选，并作为唯一通用 UI 图标集，统一尺寸、描边和选中态。官方许可页明确区分：Tabler Icons 本身采用 MIT；Tabler Illustrations 与 Tabler Emails 是另行许可的素材。该建议尚非主人最终选型。OMP 可先检查仓库已有资源，再把 Tabler 放进现有页面；若视觉上仍有明显疑问，再与 Lucide 做同尺寸小样对比。Phosphor 保留为备选，不与其它套件混用。不要先引入 Rive、Three.js 或重做前端框架。

## 伙伴交叉审阅（建议，不是最终决定）

澪核对后认为，数据驱动的关系图、真实孔位图和“未知关系明确显示待确认”的方向可行。她提出的具体建议是：

- 通用 UI 只使用一套图标，优先试 Tabler Icons；统一尺寸、线宽和选中态，避免混搭。
- 只使用开源 Tabler Icons 资源，不取用 Tabler Illustrations 或 Emails 等单独许可的素材。
- 第一轮先静态核对关系图和单个 Assay 编辑，再决定是否加入 2.5D、角色和动效。

这是伙伴的研究意见，不代表主人已选定 Tabler，也不代表视觉方案已验收。OMP 应在真实界面中核对后再建议是否定案。
## 现有界面基线：增量优化，不另起一套

以下是本轮对 web/index.html 的静态源码核对，不是截图或实机视觉验收：

- 新建设计保留四个阶段：研究目的、实验条件、检测安排、样本与检查。
- 第 3 步已有可折叠的“设计总览”，放在步骤导航之后；有检测时显示组别 × 检测关系、每项检测时间点与样本关系摘要。
- 当前关系图是静态预览。点击检测标题只跳到第 3 步，没有把该检测设为当前项或高亮关联组。
- 格子当前只显示“已选择 / 未选择”；现有契约无法区分未决定、明确不做、不适用或漏录，视图不可伪造这些状态。详见[组别 × 检测覆盖语义研究](2026-11-04-asterlab-assay-coverage-research.md)。
- 检测卡当前会同时展开检测名称、测量目标、方法、适用组、时间锚点、计划时间、时间点关系和按组安排；容器、对照、位置数、共享材料和 Protocol 位于详情区。
- 关系图在窄屏默认收起；表格有最小宽度并允许横向滚动。源码布局不能证明实际可读性，需在桌面和窄屏截图中检查字号、焦点、滚动提示与触控范围。
- 主、移动导航当前使用 Unicode 字符字形，不是 SVG 图标组件；CSS 显示尺寸为桌面 16px、窄屏 14px（`web/index.html#L11-L13`、`L102-L110`）。
- 本轮没有收到可直接检查的 CellPlanner/Lab Workbench 实际界面截图，因此不作像素级评价。

## 推荐的增量页面结构

### 第 3 步“检测安排”

保留现有设计流程、关系图和编辑卡，不替换成另一套空白向导。

**上方：设计总览**

标题和一句摘要，例如“4 组 · 2 项检测 · 时间部分待定”。图只显示当前已有事实：

- 格子只展示底层可表达的状态；若要区分「已纳入、未决定、明确不做、不适用」，先扩展契约，不能只靠视觉增加状态。
- 时间点留在检测标题或检测摘要里，不把矩阵扩成组 × 检测 × 时间三维大表。
- 选中某项检测时，高亮该列及关联组；其它关系减弱但仍可读。选中状态同时有文字/边框等非颜色信号。
- 每项检测旁始终有短摘要：时间锚点、时间点关系、样本用法状态。摘要可点到唯一的编辑位置。
- 不显示从 n、时间点或实验单位关系推算出的孔位总数。未有布局映射时由铺板工具确定物理位置。

**下方：当前编辑内容**

- 初始状态允许所有检测卡保持简短摘要；点一项后只展开那项，其他项收成一行或短卡。
- 展开的检测卡就近显示检测目标、适用组、时间锚点与计划时间、时间点关系、按组差异和来源摘要。
- 跨检测的来源材料、共享制备、分样和顺序使用在第 4 步维护；第 4 步只读汇总检测自己的时间/样本用法，不提供第二份编辑入口。
- 逐组值不同就明确标“按组不同”，不可取第一组值覆盖其他组；批量修改先预览目标组与旧值/新值。
- 容器位数、实验单位 n、实体样本数分别显示。未知值允许保存草案；只在需要生成布局、执行或解释结果时检查相应前提。

**手机排布**

同一组数据改成纵向检测卡和组别状态，不把桌面宽表缩小塞进手机。当前检测、关联组和待确认状态应在首屏可识别；完整流向图按需展开，但样本关系摘要仍可见。桌面和手机操作同一数据源，不分别维护。

### 信息层级与文字

- 主标题说明当前阶段；字段用短名词，如“测量目标”“时间锚点”“计划时间”“时间点关系”“样本来源”。
- 状态用直白短语：“已确认”“待确认”“明确不做”“与本组无关”；不用只靠颜色、表情或图形解释。
- 说明文字只解释用户当前要作的决定及影响，避免把术语定义、背景科普和全部协议文本堆在主区。
- “未知”与“不适用”分开；空白不能同时代表未知、零、未读到和明确不做。
- 视觉简洁来自层次、留白和减少重复边框，不来自缩小字号或把关键科学关系藏进高级设置。

## 图标方案比较

图标数量会随版本变化，因此不把数量当作选型依据；授权和设计规则均以官方页面为准，使用前应在项目内锁定版本并保存许可证信息。

| 图标集 | 查到的官方特征 | 适合之处 | 主要风险与候选判断 |
|---|---|---|---|
| Lucide | 官方称有 1600+ SVG；有 Vanilla JS 包，不依赖前端框架；主许可为 ISC。 | 线条清爽、辨认成本低，适合工具栏、导航和常规操作。 | 整体偏克制，未必独自提供用户想要的“灵动感”；实际引入时逐个核对所用图标是否属于 Feather 衍生清单（相应条目适用 MIT，而非 ISC）。 |
| Tabler Icons | 官方仓库当前列出 6257 个图标、MIT；设计统一为 24×24、2px 中置线条、圆角端点/连接和固定留白。 | 规格明确、SVG 资源丰富；自绘配套小图时也有可参考的格线规范。 | 当前因伙伴建议优先试用，但仍需主人确认；只引用开源图标，不把单独许可的插画或邮件素材混入。 |
| Phosphor | 官方列出 1248 个图标、Thin/Light/Regular/Bold/Fill/Duotone 六种字重，MIT。 | 可通过固定字重呈现更柔和、有性格的界面。 | 多字重会诱发随意混用；若选用，默认界面只用一种字重，状态填充另定规则。 |

- **下一步建议：**在原页面把当前字符字形作为基线，比较同一组导航项的 Lucide 与 Tabler SVG；桌面按 16px、窄屏按 14px 检查清晰度、两种主题一致性和文字层级。图标数量不作选型依据；锁定图标集前重新核对所用图标的许可与版本。Phosphor 只在研究者偏好更柔和字重时加入对比，不先混用。

### SVG 候选样张：现有字符与 Gemini 线性图标

![八个导航项的现有 Unicode 字符与原创 SVG 线性图标，在 16px 主视图和 24px 细节中的并排比较](2026-11-04-asterlab-ui-icon-exploration.svg)

样张由本次 OMP `UI` 角色（配置为 Gemini 3.8 Flash）生成；它对照源码中的八个导航字符，主列按桌面 16px 检视，另列放大到 24px。窄屏实际图标为 14px，本样张没有验证该尺寸；也没有集成进应用或做用户测试。

## 自绘、开源图标与角色的边界

### 适合开源图标库

导航、增加/删除、展开、搜索、日历、信息、警告、保存、运行状态等常规动作。它们不需要实验语义，使用成熟图标比逐个手画更一致，也更易维护。

### 适合自绘 SVG

组→检测关系、样本来源与分流、带有真实数据的步骤示意、液体转移和自定义小角色。这些内容必须从 Design/ToolUse/Run 的确定字段渲染；图上不允许出现未确认的数值、组别、孔位或样本流向。

### 需要额外规则的图

- **孔板布局**：使用准确俯视图和真实标签；2.5D 插画不能代替位置事实。
- **转移或分样示意**：未知体积显示“待确认”，不按大小画出看似精确的液量。
- **时间/进度**：计划与实际完成分开，时间间距若非按比例需标清“顺序示意”。
- **状态**：文字和形状并用，颜色只是辅助。
- **Lab Buddy**：形状保持一致，表情/小动作只代表 Agent 的空闲、处理中、等待确认、完成等状态；阻断原因仍须文字说明。

先以 SVG/CSS 做静态与少量状态动效，尊重 prefers-reduced-motion。WCAG 2.2 对交互触发动画可禁用的条文属于 AAA 级；可把减少非必要动效作为产品设计标准，不要将“有 reduced motion 代码”误说成整体符合 WCAG。Rive 可以在角色证明有用后再评估，且需分别核对运行时和创作/导出授权条件。

## 成熟产品值得借鉴的点

- **Linear**：把当前工作区作为焦点；导航和图标退后；用更少边框形成层级；以小步、可对比的方式改版。借鉴其信息秩序，不照搬深色主题或具体组件。
- **Grok Bot**：角色造型来自一组统一形状，通过可控差异区分身份；状态通过轻微变化表达；结构化内容采用适合信息本身的卡片/小组件。借鉴角色与状态语言，不让角色替代实验结果或警告文字。
- **Opentrons Protocol Designer**：流程围绕硬件/载体/步骤组织，并在当前动作上下文中编辑。借鉴“当前任务 + 相关参数”的局部聚焦；它是机器人协议设计器，不照搬其甲板和机器人限制。
- **Benchling / 现有 ELN**：可作为方法、容器、样本和执行记录的参照；只借鉴清楚的对象连接，不照搬其整套 Registry/Inventory 复杂度。
- **W3C 与 GOV.UK 表单指南**：字段有清楚标签，错误指出纠正路径；复杂多步关系不应被藏在一个条件勾选项下面。复杂来源关系要有摘要和明确的展开入口。

## 当前风险清单

1. **视觉把未知画成确定。** 每个节点和连接线要能呈现未知/待确认；缺少边时不能暗示“无分配”或“不做”。
2. **关系图与编辑器分裂。** 图只能读写同一设计对象，不能维护第二份矩阵数据。
3. **装饰太多。** 2.5D、渐变和角色可能挤压关键参数或把页面重新变成“全是字加卡片”；先让关系图减字。
4. **颜色单独传意。** 颜色之外必须有文字、形状或线型。
5. **过度缩小/横向滚动。** 390px 以下逐项检查触控、可见性、阅读顺序、焦点状态；无实际截图前不称“移动端已清楚”。
6. **复用语义混淆。** 同一预期材料供多个检测，不等于共用同一培养单位或实体样本。
7. **计数假精确。** n、样本实体数、位置数、测量次数相互独立；没有实际布局映射时不显示跨组唯一位置总数。
8. **功能状态与情绪混淆。** Buddy 不能用笑脸表达“科学正确”；校验结论必须清楚说明事实、来源和影响。

## 需要 OMP 继续研究和验证的问题

按优先级完成，先研究后改代码：

1. 打开现有 UI 或生成桌面/390px 截图，核验表单密度、层级和真实滚动体验；不要把本文件的源码观察当作像素级结论。
2. 研究 Assay 对各组是否需要三态：底层是否有“明确不做”字段？没有时先提出最小契约选择，再设计图格。禁止 UI 假造不存在的数据状态。
3. 基于现有四步，比较“所有检测同时展开”与“一个检测展开、其它收纳”的阅读效率和可发现性。保持组、时间、样本关系、保存逻辑不变。
4. 试做关系高亮，不改变实验事实：点某检测能显示其组覆盖和时间/样本关系；地图与编辑卡双向定位，移动端仍可操作。
5. 选同一案例对照 Lucide/Tabler；列出实际需要的图标清单、各自易混图标和项目许可记录，不以图标数量做结论。
6. 用 L929 + GelMA 和生物膜两种不同密度设计检查关系图；SA 梯度检查大量组与部分检测；动物纵向或组织/组学案例检查非孔板载体。
7. 只在关系/步骤图能降低理解负担后，评估加样 2.5D 示意；图示要绑定参数数据、保持“示意”标签，真实板孔另用俯视图。
8. 最后再讨论原创 Lab Buddy；先说明是否改善状态识别/反馈，再决定 SVG 静态角色或 Rive。

## 验收条件

- 保留现有四阶段流程，先在原页面做小范围增量；不另造空白原型再取代。
- 关系图和编辑器共享同一份数据；组、检测、时间、时间点关系的未知值保存后再读回仍一致。
- 检测切换会把视线定位到正确检测，关掉/打开其他卡不会改任何科学关系。
- 显示明确“不做 / 未决定”之前，API 和存储都必须能保存、校验和往返这两种状态。
- 组级关系有差异时完整保留；批量修改先显示受影响组和变更前后值。
- 不从 n、同一实验单位复测、时间点个数直接推导实体样本或孔位总数。
- 不同分支、D1/D3、板/管/切片/动物上下文不能串。
- 视图对桌面和窄屏均可理解；非必要动效可减弱或关闭。
- 实际研究者测试以前，只报告“静态走查/原型比较”，不报告“用户体验提高”。
