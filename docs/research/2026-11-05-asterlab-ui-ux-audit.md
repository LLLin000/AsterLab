# AsterLab / Lab Workbench 全界面 UI/UX 走查

> **目标**：从一线实验操作者视角检查导航、页面分区、字段文字、单位、入口重叠与窄屏布局；给出可评审的收敛方案。本文是研究建议，不代表 UI 已实施。

- 审计日期：2026-11-05
- 基线：仓库提交 `bf1f0e9`
- 代码范围：`web/index.html`、相关前端表单/渲染与 `src/main.rs` 校验；对照 `HANDOFF.md`、既有实验设计模型和视觉语言研究。
- 浏览器走查：本机隔离数据库；桌面 1440px 与窄屏约 390px；覆盖 11 个导航目的地、项目空态、向导、日历与计算器等页面。
- 隔离数据：只创建过两个临时项目元数据用于看项目卡片；没有写入真实实验设计、Run、样本、孔位或执行事件。未触碰默认数据库 `data/labworkbench.sqlite`。
- **没有开展真实操作者用户测试**；截图/运行时观察不能替代用户测试，也不能证明任何实验流程适配性。

## 1. 结论先行

1. **主问题不是侧栏分组标题，而是 11 个同权入口暴露了不同层级的对象。** 工作台、项目、设计、日历、运行互相重复；孔板、记录、资料表、公式、计算器也被提升为全局入口。目标应是 4 个主要去处，并把设计、运行、记录、孔板和工具放回它们的上下文中。
2. **项目页目前不是工作区。** 项目卡片的“打开项目”实测无响应；设计与 Run 仍靠独立导航和顶部项目筛选器访问。不能先删“实验设计/实验运行”入口再补项目详情页；应先打通项目详情与下钻，再收敛导航。
3. **实验设计、操作方法模块、执行事实是三种不同对象。** “从已有实验起步”中的 L929、SA、生物膜是完整实验设计，不是可复用的小步骤。应从设计表单/方法模块入口移除这类整套实验选择器；可复用的步骤模块单独加入方法库，再由操作方案引用。
4. **全站多行文本框共用一个错误占位提示。** `area()` 对项目说明、实际记录、观察、偏差、公式说明等都显示“按本实验方案填写；留空表示尚未提供”。这是全局文案根因，不应逐个页面打补丁；每个字段要显示“填什么、为何填、可否留空”，示例只放在对应字段。
5. **浓度/体积值与单位必须作为一个输入组。** 当前计算器把数值和单位拆成独立网格项；记录材料用量/读数、Protocol 参数绑定也有相同问题。移动端尤其会出现先输入几个无单位数字、最后才选择单位的顺序。
6. **窄屏有真实布局问题。** 390px 下侧栏变成含 11 项的横向滚动导航；日历 7 列总宽约 944px，首屏只显示约 2.5 天；公式库短页面在导航下方留出明显空白带。
7. **另有两个已确认的误导/误操作点。** 未记录发生时间的执行记录会被日期筛选直接排除；设计向导可点击遮罩关闭且不提示未保存，已实测未保存输入被丢弃。

## 2. 证据等级与成熟设计语言

- **[源码]**：由当前实现或数据校验直接确认。
- **[浏览器]**：在隔离实例、指定视口观察或操作确认。
- **[建议]**：本报告的候选交互与文字，仍需产品评审；不等于现有能力。
- **[待确认]**：当前数据模型或真实实验流程不能从 UI/源码判定，不应由界面猜测。

本次只借鉴成熟系统的**信息秩序**，不照搬其外观：
- [Linear 设计刷新](https://linear.app/now/behind-the-latest-design-refresh)：当前工作区优先、导航退后、减少平级噪音和无意义分隔线。
- [W3C WAI 表单标签](https://www.w3.org/WAI/tutorials/forms/labels/) 与 [GOV.UK Text input](https://design-system.service.gov.uk/components/text-input/)：字段必须有可见、短而明确的标签；提示/示例不能替代标签，输入后提示也不应消失。
- 项目自身的四入口与手机布局基线：[`2026-11-02 实验设计模型`](2026-11-02-cellplanner-experiment-design-model.md#导航与对象关系)、[`HANDOFF.md` 页面层级](../../HANDOFF.md#7-建议的页面层级与文案候选)。

## 3. 入口与对象层级：从 11 项改成 4 个主入口

### 3.1 当前重叠（源码事实）

| 当前页 | 现在展示/操作 | 重复或错位 |
|---|---|---|
| 工作台 | 4 个静态指标、流程示意、项目卡、完整 Run 卡、前 5 个未完成任务 | 项目/Run/任务又各有完整独立页；指标无下钻且统计范围随项目筛选改变。 |
| 项目 | 项目卡片和计数 | “打开项目”按钮没有处理分支；列表不能进入该项目的设计/Run。 |
| 实验设计 | 全局设计列表，设计卡又包含 Run 列表/创建 Run 操作 | 实验作为项目子对象被拆成一个全局入口，Run 又出现在设计卡与 Run 页。 |
| 日历与任务 | 周网格同时放 Run 日期与 Task；下方又列 Task | 与工作台重复任务；Run 日期修改和 Task 排期入口分散。 |
| 实验运行 | Run 卡片 | 工作台复用完整 `runCard`；卡上再放操作台、事件、文本记录、排期、状态、铺板等多个按钮。 |
| 实验记录 | 全局记录筛选与写入 | 新增记录/实际事件还出现在 Run 卡；全局按钮默认带入第一条 Run，不一定是操作者当前要记录的 Run。 |
| 铺板布局 | 独立导航页 | 操作台也呈现板图；页面说明却称“当前安装版…没有发现独立铺板界面”。 |
| 资料表 / 公式库 / 计算器 | 三个平级导航 | 辅助工具与核心科研流程同权，且没有说明何时使用哪一个。 |

### 3.2 建议的目标 IA

| 主入口 | 唯一回答的问题 | 下沉的对象与入口 |
|---|---|---|
| **今天** | 今天有哪些已排期事项、哪些 Run 正在进行？ | 今日待办只呈现手工创建的 Task；进行中/今天排期的 Run 提供“进入操作台”。不自动从设计时间点生成任务，不把 Task 完成当成执行记录。 |
| **项目** | 这个课题有哪些实验设计与执行批次？ | 项目详情内展示实验（Design）与其 Run；新建设计从项目上下文开始，Run 从对应设计创建。 |
| **日程** | 哪些批次和提醒排在什么日期？ | 汇总 Run 的计划日期与手工 Task，明确区分“批次排期”和“待办提醒”；这里是 Task 排期维护主入口。 |
| **方法库**（Protocol） | 哪些小步骤可复用？有哪些完整操作方案？ | 同页明确分成“步骤模块”和“操作方案”；工具调用引用上下文，不增加一组平级导航。 |

**上下文入口**：孔板在 Run 操作台内；实际事件/文本记录在对应 Run 内；资料表、公式与计算器从工具入口或相关任务上下文打开。工具与实验设计分开，不能把科学组别/n/假设复制进工具。

**迁移约束**：目标 IA 不等于立即删除当前页。先实现“项目卡片 → 项目详情 → 设计 → Run”的可用链路，再把“实验设计/实验运行”降为上下文页；此前保留可达路径，避免因删导航让功能消失。顶部项目选择器在过渡阶段保留，项目详情成熟后改为当前项目面包屑/上下文，而不是第二套导航。

### 3.3 桌面与手机的页面顺序

| 页面 | 桌面从上到下 | 手机 |
|---|---|---|
| 今天 | 标题/日期 → 今日待办 → 进行中 Run → 空状态或继续入口 | 单列；每卡一个主动作；不放统计卡、项目目录或完整 Run 管理按钮。 |
| 项目 | 项目列表 → 项目详情（实验设计 → 对应 Run） | 单列卡片；面包屑收起到项目名；设计/Run 依次纵排。 |
| 日程 | 日期控制 → 7 日周视图 → 未排期 Task/Run 清单 | 单行日期选择 → 选中日的垂直事项清单；不要求横向拖动 7 列网格。 |
| 方法库 | 步骤模块 → 完整操作方案 | 两区纵排；保持单一主标题，分区标题直接说明用途。 |
| Run 操作台 | 批次/检测上下文 → 左侧步骤列表 → 当前步骤/参数/板图/记录 | 当前检测与当前步骤先显示；步骤、参数、板图、记录纵向展开；关键关系不藏在横向滚动里。 |

## 4. 各屏与各块的详细走查

### 4.1 全局外壳与导航

- **[源码/浏览器]** 桌面侧栏 3 组、11 项；约 232px 宽。390px 时改成横向滚动的 11 项导航，首屏只能看到约 5–6 项且边缘有半个项目。
- **[建议]** 桌面只留“今天 / 项目 / 日程 / 方法库”；手机改为 4 项紧凑底部导航（处理设备安全区），不保留 11 项横向条。去掉“工作流/实验资源/数据与工具”三个分组后，不是把剩下 11 项平铺，而是按上表下沉对象。
- 顶栏“当前项目”选择器和全局导出是次级操作；进入项目后显示项目上下文。导出按钮应说明范围（当前项目/全部本机数据），避免用户不知道导出什么。
- **[浏览器]** 公式库页面在 390px 下，侧栏容器高度约 222px，而品牌与导航内容约在 y=85px 结束，留下约 137px 空带。应让窄屏导航只占自身高度，不保留桌面侧栏的整行高度。

### 4.2 工作台 → 今天

- **[源码]** 当前首页将全局项目数与当前筛选范围的设计/Run/Task 计数并列；指标没有点击下钻。项目卡、完整 Run 卡、任务又出现在独立页面。
- **[建议]** 改为“今天”行动页：只显示今天/超期的手工 Task（标为“待办提醒”）与正在进行/今天排期的 Run（“进入操作台”）。今天是完整日程的过滤视图，不再复制项目列表、四张完整运行卡或装饰性工作链。
- 不能显示“待补记偏差”之类系统无法判断的状态；只能显示已存在的偏差事件或明确标记的事项。Task 完成只代表关闭提醒，不代表样本、操作或结果已记录。
- 让首页一个主问题对应一个主要动作；创建 Task 和修改日期统一到日程，Run 事件录入从操作台进入。

### 4.3 项目列表与项目详情

- **[浏览器]** 点击非当前项目卡片的“打开项目”没有反应；顶部项目选择器仍可切换项目，但它不是卡片承诺的动作。
- **[源码推断]** `projectCard()` 统计设计与 Run 时读取的是已按当前 `activeProject` 筛选的记录，所以切到项目 A 后查看项目 B，B 的卡片计数可能显示为 0。
- **[建议]** 卡片主动作改为真正的“打开项目”；项目详情中按“实验设计 → 该设计的执行批次”组织。卡片只保留项目名、说明、设计数/运行数和一个入口。设计/Run列表不要再分别成为与项目同层的主导航。
- 项目表单：`项目名称` → 提示“例如：水凝胶材料评价”；`项目说明` → “可写项目范围或管理备注；暂时没有可留空。”删除该字段里的通用“按本实验方案填写”提示。

### 4.4 实验设计列表与四步向导

#### 整套实验示例与方法模块必须拆开

- **[源码]** 设计列表与向导出现“从已有实验起步 / 用既有实验记录试填”，并列出 L929 多检测、SA 梯度、生物膜多检测。
- **决策**：从新建设计和方法模块入口移除这组“整套实验”选择器。它们包含研究目标、组别、检测与来源关系，不是可以插进另一实验的小步骤。若要保留示例内容，必须明确为只读参考，不得用“模块/方法/复用步骤”命名，也不应占设计列表首屏。
- 方法模块是独立的小操作，例如“加入试剂”“孵育”“读数”；之后由完整操作方案引用。具体实验参数来自当前实验/操作者，不从其他完整实验案例静默带入。

#### 四步顺序与字段文字

| 步骤 | 保留的科学任务 | 当前困惑 | 建议显示文字与填写说明 |
|---|---|---|---|
| 1 研究目的 | 定义要回答的问题 | 当前先显示大文本“研究目的”，名称排在后面；名称下的辅助说明是操作指引，不是示例。 | 先“实验设计名称”后“研究目的”。名称例：“材料 A 对细胞活力的影响”；目的提示：“用一两句话说明要比较什么；未知条件可留空。” |
| 2 比较条件 | 组别、处理、实验单位与重复 | 组名/处理主要靠 placeholder；角色只有“角色可选”；“实验单位”不直观。 | 标题可改“分组与处理”；每张组卡显示可见标签“组名”“处理条件”“组别类型（可选）”。实验单位写成“什么对象算一个独立样本？”提示“如一只动物/一次独立制备；孔数不等于独立 n；不确定可留空”。保持 n 与技术重复分开。 |
| 3 检测安排 | 每项检测、适用组、目标、时间与来源 | “时间锚点”“时间点关系”“容器/载体”偏系统语言；方法说明“仪器参数在工具中设置”不指出具体位置。 | “时间锚点”→“从哪个事件开始计时”；“计划时间”→“计划检测时间点（每行一项）”；“测量目标”→“要记录的读数/指标”；“方法名称或版本”说明“可填方法名称；完整操作步骤在下方选择操作方案”。`组别/检测/时间点关系`的未知状态继续保留“待确认”，不替用户填科学事实。 |
| 4 样本与检查 | 跨检测来源、共享制备物与证据冲突 | “共享材料”不说明是否指市售试剂；“计划执行轮次/轮次之间的来源关系”与样本来源混在一起；“兼容旧设计”字段重复第 3 步。 | “共享材料”→“跨检测共用的自制材料”，说明“同一次制备分给多项检测；常规市售试剂不用填”。“计划执行轮次”与“轮次间来源关系”并入“重复安排（可选）”。“主要读数摘要/方法摘要/单位摘要/总体时间点（兼容旧设计）”不再出现在新设计常规表单；历史数据仍可读取，需确认兼容后再改。 |

**向导逐字段文字补充**：
- `检测名称`：例“CCK-8 细胞活力检测”。
- `适用组`：说明“勾选这项检测会用于哪些组；不同组可不同”。
- `时间点关系`：在选项下方直接问“这些时间点是同一实验单位继续观察、反复测同一份样本，还是每个时间点另取样？不确定请选择‘待确认’。”不把不同关系合并成“重复”。
- `统一设置：每组位置数（每个时间点）`：说明“填写计划占用的孔/位置数；不等于样本数或独立 n”。
- `统一来源检测` → “这项检测的样本来自哪项检测（可选）”；“不指定”含义写清楚是“新取样/来源待确认”，不能让空白兼表“没有来源”。
- `补充说明`变量实际用于检测补充内容，与“关联对照组”重名近似；改为“检测注意事项”。
- “返回总览”是回到第 1 步的检查跳转；表单底栏已有“保存设计”。它不是“最终保存”按钮，本次不列为缺陷。可考虑改名“返回第 1 步检查”以免误认。

**向导未保存输入风险**：
- **[浏览器]** 输入设计目的后点击模态框遮罩，向导直接关闭，输入未保存且无确认。建议脏表单关闭时提示“放弃未保存的设计草稿？”；“取消”与“放弃”分开。此项为编辑草稿的防丢失措施，不改变科学数据契约。

### 4.5 日程与待办

- **[源码/浏览器]** 工作台和日程都显示任务；周格同时显示 Run 与 Task；下面又列出全部 Task。Task 是手工创建的标题、日期、状态、备注；设计时间点不会自动变成任务。
- **[建议]** 主导航名用“日程”；在页面内将两类对象分组显示：`批次排期`（Run 的计划日期）与`待办提醒`（Task）。不要把运行、操作步骤和自由待办都塞成同一种日历块。日期尚未填写的任务明确显示“日期待定”，不显示 `null`。
- 任务表单文字：`任务名称` → `待办事项`，提示“写一个可执行的提醒，例如准备培养基”；`关联实验运行（可选）`保留；`计划日期` → `计划执行日期`，说明“这是排期，不是实际发生时间；未确定可留空”；`备注` → `排期说明（可选）`，说明“写前置条件或提醒；实际结果另在运行记录中填写”。
- `更新状态`目前按按钮点击循环 `计划中 → 进行中 → 已完成 → 受阻`；提示“点击状态按钮循环切换”要求用户先记住循环次序。用明确状态选择器替代；若标记 Task 完成，仍说明这只结束提醒，不自动创建实验事件。
- **[浏览器]** 手机日历首屏约显示 2.5 天；样式最小列宽 128px，7 列加间距约 944px。桌面周格可保留 7 列；手机改日期选择 + 单日列表，确保周四至周日不是隐蔽横向内容。

### 4.6 Run 与操作台

- **[源码]** Run 在设计下；创建时冻结所引用的设计与 Protocol 版本。Run 卡同时提供操作台、记录事件、新增文本记录、改排期、改状态、铺板等多个同权按钮；首页再复用完整卡片。
- **[建议]** Run 列表在项目/设计下收拢；卡片主按钮只保留“进入操作台/继续记录”，其余操作在 Run 内的明确位置。真实事件只从对应 Run 上下文录入，避免全局入口默认选中第一条 Run。
- 新建 Run 表单：`运行名称` → `执行批次名称`（例：“2026-11-05 · CCK-8 第 1 批”）；`关联设计及其当前版本` → `依据的实验设计与版本`；`计划开始日期`说明“仅为计划日期；实际时间在记录中填写”。
- `旧式全局 Protocol（可选）`是过渡期术语。若字段仍需保留，改为“额外操作方案（可选）”并说明何时需要；是否隐藏要先核实旧数据/调用契约，不能只为变短删除。
- `再次执行来源/与上一轮的来源关系`改为“参照的上一批次（可选）”与“本批次和上一批次的来源关系”，说明“独立来源/同一来源/配对或区组；不确定选待确认”。不要把“技术重复”当成“同一来源”的默认解释。
- **状态按钮**：卡片上的“改状态”目前是循环更新，操作者看不到下一步会变成什么。改成显式菜单显示目标状态；不新增自动完成事件。
- 操作台具体步骤/参数在本次无法以真实 Run 完整运行时逐条走查（隔离库没有真实设计/Run）。源码可确认其包含步骤、参数、图解、板图与事件区；参数代码如 `target_percent` 不应直接露给操作者，应显示“显示名称”。Run/步骤状态不能由系统凭空推断。

### 4.7 方法库：操作方案与步骤模块

- **[源码]** 当前 Protocol 页已经有两个区：上方“步骤块”，下方“Protocol 库”；这比把整套实验案例作为模块更接近用户要求，无需再添一个主导航入口。
- **[建议]** 显示为：
  - **步骤模块库**：通用的小操作，声明每次需要填写的参数及单位，不包含特定实验组别/研究假设。
  - **操作方案库（Protocol）**：由步骤模块组合，或直接录入简短的文本规程；用于某项检测或材料制备。
- 把“块”改为操作者理解的“模块”；把按钮“新建 Protocol”改为“新建操作方案”。不要在方法库里出现 L929/SA/生物膜等整套实验选择器。
- 步骤模块表单：`步骤块名称` → `步骤模块名称`，例“加入检测试剂 / 孵育等待 / 读数”；当前例“制备 GelMA 浸提液”容易让用户以为整套制备流程是一个最小步骤。`可变参数`说明“声明本步骤每次需要填写的条件和单位”；`参数 key`是内部标识，可见名改为“参数代码（英文，用于系统引用）”，旁边保留操作者能读懂的“参数名称”。通用说明里去掉“Agent 可把…”这类内部实现术语。
- 新建操作方案表单：`操作内容来源` → `步骤内容来源`；`使用自由文本 Protocol` → `直接填写文字规程`；“旧式 Protocol 正文”改为“文字规程内容”。
- 参数绑定当前把单位拼在标签尾部。应把单位紧跟对应数值框；必填字段要说明“草稿可保存；完整使用前需补齐”，避免“必填参数；未知可留空”自相矛盾。

### 4.8 铺板布局与孔位

- **[源码/浏览器]** 页面顶部文案声称“当前安装版……没有发现独立铺板界面”，但用户正处在铺板页面，语义自相矛盾。替换为“这里记录 Run 中实体板的规格与孔位；设计中的位置数是计划值，实际板图由操作者填写”。
- 新建板图字段：`布局名称`→`板图名称/编号`；`关联实验运行`说明这是必选的所属批次；`关联检测（可选）`说明“需要在该检测操作台查看板图时请选择”；`此板对应的时间点`说明“检测要求每个时间点使用新样本时必须填写”。
- **[源码]** 选择 96 孔等标准板型后，行数/列数输入仍可编辑；后端只检查范围，不检查它们与 `format` 是否一致。因此可保存“格式为 96 孔、行列却不是 8×12”的记录。标准板型尺寸应只读；只有选择“自定义”时编辑行/列。
- 孔位表单中组别/条件标签和样本编号是自由文本。建议在 Run 上下文提供当前设计组别可选列表，减少重复手输和拼写差异；若当前映射数据不足，保留手工输入并明确“按本 Run 设计填写”。不要从空孔推断空白、边缘水孔或未使用孔的科学角色；当前界面只知道“尚未映射”。
- 单孔点击弹出模态、一次编辑一个孔；大板操作成本高。作为后续验证点，先检查真实用户是否需要批量映射；不直接引入复杂绘图或猜测性排板算法。

### 4.9 实验记录与实际事件

- **[源码]** 全局记录页同时有“新增文本记录”和“记录实际事件”；两者内容重叠但数据结构不同。普通文本域占位符错误地说“按本实验方案填写”。
- **[建议]** 入口分主次并定义含义：主按钮“记录实际情况”（操作/材料/读数/偏差）；次按钮“新增文本记录”（自由文字备忘）。进入 Run 操作台时自动关联当前 Run；全局查询页不要默认把记录挂到第一条 Run。
- 多行文本域的共用根因：`area()` 应接受字段专属 placeholder/hint。字段建议：
  - `记录内容` → “实际做了什么/观察到什么”；示例提示为实际发生的事实，不要要求抄方案。
  - `观察` → “写实际看到的现象；尚未观察可留空”。
  - `结果` → “填写实测结果；没有结果可留空”。
  - `实际偏差内容` → “只记录已经发生的偏差；没有偏差可留空”。
  - `样本编号` → “多个编号每行一个”。
- **单位并组**：材料用量 `数值 + 单位`、测量读数 `数值 + 单位`应同行紧邻。当前“用量单位（可选）”与提交校验冲突：填用量时单位实际必填，文案须改为“用量可留空；填写用量时请同时填写单位”。
- **筛选器行为缺陷**：日期范围筛选会排除 `occurred_at` 为空的事件，而记录提示又允许时间不确定时留空。提供“包含发生时间未详记录”或改变过滤规则，并增加清除筛选动作；用户不应误以为无时间记录已丢失。
- 空库与无匹配结果分开写：“暂无记录” vs “当前筛选没有匹配项”。当前记录更正提示已写明“追加更正并说明依据”，保留该原则，不称为缺失。

### 4.10 计算器

| 模式 | 当前结构问题 | 建议布局（数值与单位同组） |
|---|---|---|
| 稀释 | C₁、C₂、V₂ 三个数值先出现，三个单位下拉后出现；桌面网格也把单位放到后续行。 | `储液浓度 C₁ [数值][单位]`；`目标浓度 C₂ [数值][单位]`；`目标体积 V₂ [数值][单位]`。桌面两列并排浓度、体积另起完整字段；手机单列但每个字段内单位紧跟数值。 |
| 溶液质量 | `终体积`与“体积单位”分开，分子量字段插在中间。 | `目标浓度 C [数值] mol/L`（当前固定单位保留为后缀）；`终体积 V [数值][L/mL/µL]`；`分子量 MW [数值] g/mol`。不在本研究中擅自增加浓度单位选项。 |
| 系列稀释 | 初始浓度单位单独成格；转移体积/稀释液体积没有单位控件，只写“使用相同单位”。 | `初始浓度 [数值][单位]`；两个体积各自显示同一单位后缀。单位用一个共享选择，还是固定显示某单位，属于待确认决定；不能继续不标单位。 |
| 反应体积 | 组分体积与单位在标签中；“水的体积”是可编辑输入，说明却说自动计算。 | 组分 `名称 + 体积[数值] µL`；目标总体积同样显示 `µL`。将“水的体积”做成计算结果只读输出“剩余未分配体积”，避免要求操作者填写会被覆盖的数值。 |

**通用**：单位选择器是输入值的组成部分，不能排在独立一行；手机保持值+单位同一视觉组。结果保留单位和“算术结果不等于实验建议”的边界说明。

### 4.11 资料表与公式库

- **资料表**：提示“每行一个列名，或用 Tab 分隔”会让人以为可在文本框按 Tab 键输入；浏览器默认会把焦点移走。改为“每行一个列名；也可从 Excel 复制粘贴表头/数据（单元格以 Tab 分隔）”。表名必填；空表可保存。卡片只显示前 8 行，应明确“预览前 8 行，共 N 行，编辑查看全部”。
- **公式库**：变量区缺少格式例子；卡片会把变量多行内容折叠成一段。使用“变量与单位说明”，提示“每行一项，格式：符号 — 含义（单位）”；卡片保留换行。表达式只存文本、不执行的说明应保留。
- 两页顶部说明都可变短：资料表说明“存放跨次查阅的结构化参考数据，不记录本次实验结果”；公式库说明“存放可复用的计算表达式与单位约定，本地版本不执行公式”。说明要回答何时用，而不是堆免责声明。

## 5. 优先级与实现顺序

优先级表示对用户理解/操作的影响，不代表合规审计等级。

### P1：先解决入口、语义与误导
1. 先打通项目详情/下钻与“打开项目”，之后再移除设计/Run 顶层入口。
2. 从设计流程移除“从已有实验起步/既有实验试填”整套实验卡；方法模块作为独立步骤加入方法库。
3. 替换 `area()` 的统一计划占位符；为实际记录、项目说明、公式等提供字段专属提示。
4. 计算器、事件录入、Protocol 参数字段全部把数值与单位合并成输入组。
5. 修正设计遮罩关闭丢失、记录日期筛选排除无发生时间事件、Task 状态循环无目标预览。
6. 标准板型行列只读；铺板页删除自相矛盾的脚手架说明。
7. 手机日历改为选日+单日列表；四项导航取代 11 项横向滚动条。

### P2：提升扫读和清晰度
1. 收拢首页重复指标/项目/Run 卡，改为今天视图。
2. 收短并具体化各字段的标签、示例、必填/选填、单位与影响说明。
3. 资料表预览标明截断，公式变量保留换行；清楚区分文本记录与结构化实际事件。
4. 评估孔位组别选择和大板批量映射需求；未验证前不做复杂映射工具。

## 6. 后续验收条件

- 一级主入口为“今天、项目、日程、方法库”；移除其他入口前，项目→实验设计→Run→操作台路径可从项目详情完整到达。
- 设计案例不会再被呈现为操作方法模块；步骤模块可独立创建、引用与组合，不携带整套实验的组别/假设。
- 每个字段有可见标签；读者能回答“填什么、示例是什么、可否留空、值会影响哪里”。
- 每个浓度/体积数值后紧邻单位；390px 下单位不另行掉到后续行。
- Task 关闭提醒不生成虚构实验事件；计划值与实际值始终有明确区别。
- 390px 日程首屏可切换一周任意一天；记录筛选不静默隐藏无事件时间的记录；未保存设计关闭有明确确认。
- 项目卡片、导航、按钮都能执行其文字承诺的动作；不出现死按钮或相互矛盾的脚手架文字。
- 真实操作者走查后再确定科研术语、孔板映射和方法库的最终文案；本报告不把桌面走查称为用户测试。
