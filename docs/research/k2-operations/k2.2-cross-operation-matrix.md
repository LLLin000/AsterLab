# K2.2 跨操作契约矩阵

- 日期:2026-11-05
- 状态:五份 `research_draft` JSON;没有第二人科学复核;不能产生 `Compatible`,不能进入 K3。
- 范围:`liquid_transfer`、`sample_aliquot`、`incubation`、`washing`、`absorbance_measurement`。
- 目的:用五个不同类型操作检验 `OperationModule` 是否能表达物质转移、样本谱系、时间、状态变化和测量。

## 1. 五个操作

| 操作 | JSON | 关键端口/转换 | 当前能表达 | 当前不能表达 |
|---|---|---|---|---|
| 液体转移 | `catalog/operations/liquid-transfer.v1.json` | source → source_remaining/transferred;条件 `partial/full/add_to_existing` | 三种关系通过 `applies_when` 条件分支表达;体积只看正数,具体范围留给 profile | 条件分支的运行时选择;来源剩余体积的数值变化;目标已有内容的具体身份 |
| 取样/分样 | `catalog/operations/sample-aliquot.v1.json` | parent → parent_remaining + aliquot | 父子样本、多个子样本、父本保留 | 剩余量/分样量的数值守恒;样本 ID 生成规则 |
| 孵育 | `catalog/operations/incubation.v1.json` | culture_in → culture_out;`state_changed` | 持续状态、时间锚点、实际开始/结束记录字段 | 实际状态变化(贴壁/生长)的类型化;Anchor 的自动计算 |
| 洗涤 | `catalog/operations/washing.v1.json` | sample_in → sample_out;buffer → waste | 同一身份保留/状态改变、废液、防干燥、样品丢失失败 | 洗涤导致的样本损失作为独立效果;残留体积的确定性计算 |
| 吸光度测量 | `catalog/operations/absorbance-measurement.v1.json` | plate_in → plate_out + raw_measurement | 原始读数、非消耗测量、数据元信息;仪器范围/方法要求分离 | Assay 特定空白/标准曲线;具体波长/板型的自动匹配;仪器范围与线性范围区分 |

## 2. 与仪器 Profile 的关系

- 液体转移 → `pipette` profile;只要求 `volume_range` 存在,具体体积由绑定/后续检查核对。
- 吸光度 → `plate_reader` profile;只要求 `wavelength`/`plate_format` 能力存在,不把 200–1000 nm 或 96/384 写成通用操作约束。
- 孵育 → `incubator` profile;只要求温度/CO₂ 能力存在;实际设定值来自协议/绑定。
- 洗涤 → 当前没有强制仪器;手动/洗板机是变体,不能默认绑定某一类。
- 取样 → `pipette`;与液体转移共享能力,但样本谱系不同。

## 3. 契约扩展

K2.2 新增/使用了三个通用能力,不是为某个操作特制:

| 扩展 | 用途 | 限制 |
|---|---|---|
| `SampleEffect::Moved` | 全部转移/换容器,样本身份保留 | 仍需输出端口;不表达数量变化 |
| `ParameterConstraint::Positive` | 正体积/时长/计数 | 只校验数值 >0;实际上限由 profile/方法约束 |
| `SampleTransition.applies_when` | 条件转移(如 transfer_mode) | 只引用模块参数;运行时选择未实现 |

## 4. 总结:契约能表达/不能表达

### 能表达

- 不同操作的端口和样本转移关系;
- 条件转移分支(结构层);
- 同一输入产生多个输出(分样);
- 状态改变与终端/保留/消耗;
- 时间作用域默认/允许集合;
- 参数来源、确认阶段、正数/范围/枚举约束;
- 操作与仪器能力分离。

### 不能表达(需要后续模型工作)

1. 数值守恒:父样本剩余量、分样量、洗涤残留量。
2. 样本 ID/谱系生成规则(目前只在 record fields/notes 里)。
3. 条件转移的实际选择与执行(K2.2 只有结构)。
4. 实际状态变化类型(贴壁、生长、损伤)。
5. 洗涤中样本损失作为独立 effect。
6. 仪器 profile 与本次绑定体积的跨字段校验。
7. Assay 特定对照/空白与通用操作的分层仍靠文档,不是 JSON 类型。

## 5. 验证

```text
cargo test -p asterlab-core --test catalog_drafts
cargo test -p asterlab-core --test operation_surface
cargo test -p asterlab-core operation_module
```

- 五份 JSON 全部通过 `OperationModule::validate_contract()`;6 个 surface 测试检查条件模式、父/子身份、时间锚点、洗涤废液、吸光度分层和 research-draft 状态;
- 两份 profile 通过 `InstrumentProfile::validate()`;
- 草稿 profile 只能得到 `Unknown`;
- `liquid_transfer` 的条件 transition 引用 `transfer_mode`;
- `Moved` 必须有输出端口;
- `Positive` 拒绝 0。

## 6. 决策

- 不继续复制同一份 JSON 到更多实验;先做第二人来源复核。
- 不进入 K3;不生成正式 ProtocolBlock。
- 不把 `applies_when` 当成已执行的模式选择。
- 不把通用操作参数写成某型号规格。
