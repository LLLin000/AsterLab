# CellPlanner UI/UX 评审草案：设计画布与独立工具区

日期：2026-11-03
状态：候选方案，待实验场景走查与用户验证；不是冻结规格。现有四步新建设计只做了小范围增量试做。
范围：在现有新建设计流程上增加关系可视化，并梳理样本关系、工具入口和 Agent 操作契约；不另起一套新 UI。

## 结论先行

目前更稳妥的方向是：**保留现有四阶段编辑流程，在组别和检测逐步形成时附上一张实时关系图；不推翻已经完成的编辑器。**工具仍作为独立一级工作区，按任务调用；设计、方法、工具使用和实际执行通过稳定引用衔接。

关键修正：样本关系不能只在“关系不清”时出现。它应始终有一条短摘要；只有分样、共用、终末用途、关系冲突或数量计算依赖它时，才展开完整流向图。矩阵只表达组与检测的覆盖，时间点作为每项检测自己的安排，不构成矩阵第三维。

这是一项当前最有根据的候选，不等于已通过可用性测试。矩阵主视图与检测卡主视图仍应拿真实案例比较。

## 设计边界

| 对象 | 用户要回答的问题 | 不负责什么 |
| --- | --- | --- |
| 实验设计 | 比较什么；有哪些处理组；测什么；哪些组做哪些检测；测量时间；样本计划关系 | 仪器旋钮、实际孔位、实际读数 |
| Protocol / 方法块 | 怎样完成一个操作；方法参数、单位、来源、适用范围和版本 | 重新定义组别、独立 n 或样本分配 |
| 工具中心 | 用已有方法做一次铺板、填板、计算或仪器任务；预览并应用工具结果 | 复制一份科学设计或伪造实际执行事实 |
| Run | 冻结所选设计与方法版本；记录实际材料、载体、设备、设置、事件和数据来源 | 静默改写已冻结计划 |

UI 一级入口可叫“工具”；为避免与模型函数混淆，Agent API 内部称“动作”或“操作”。工具目录可引用现有 ProtocolBlockVersion，后续不另建一套重复步骤正文和版本源。

来源材料、实验单位、分样、容器、读数是不同关系。共用一种制备材料不等于共用一个培养单位；孔、切片、视野或重复采集也不自动增加独立 n。软件不得从名称或孔数推断这些关系。

## 新建设计的候选流程

### 入口：允许从已有工作开始

一屏提供四种入口：一句话描述、复制已有设计、导入记录、手动添加。它们都写入同一份 Design 草案，不另设 Agent 草稿对象。导入先呈现识别出的内容、原始来源和冲突；解析结果不是自动确认的科学事实。

草案允许不完整地保存。未确认的处理水平、对照、时间、n 和样本关系保持“待确认”；不填 0、不补默认、不把空值解释成“不做”。

### 主画布：比较条件、检测覆盖、样本关系摘要

```text
设计名称 · 草案                         保存
研究问题 / 比较意图

处理条件   [对照 · 待确认] [水平 A] [水平 B] [+ 批量添加梯度]

检测覆盖   组别          CCK-8       活死成像      RNA-seq
           对照          做 · D1/D3   待定          不做
           水平 A        做 · D1/D3   做 · D3       不做
           水平 B        做 · D1/D3   做 · D3       做 · D3

样本关系   计划来源：待确认；不同检测是否共用培养单位：待确认
           [查看样本去向]

当前要确认  是否同一培养单位分样？这会影响样本需求和检测安排。
```

这只是布局示意；“对照”、组别、检测和时间均应来自用户或记录，不由软件预填。

- 覆盖格至少区分“做”“不做”“未决定”。空白不能同时表示零、未读到、待填和不适用。
- 时间是每项检测自己的设置，可用相对锚点并支持按时间筛选。不要展开成组 × 检测 × 时间三维巨表。
- 对常见规模可以用矩阵快速批量编辑；手机端将同一关系转换成逐检测卡片和组别标签，不能靠缩小字号挤进宽表。
- 样本关系始终保留一行摘要。检测共享材料与共用实验单位分开写；已知关系也不藏。分支、终末用途、顺序复用、混样或冲突时再展开来源流向图。
- 每次批量应用都显示范围，例如“将 D3 应用于 4 个已选组”。用户明确排除的格子不被覆盖。
- 标题、描述和长篇解释不抢主画布；每项检测显示指标、组覆盖、时间和样本用法的短摘要。

### 问题与校验按用途分层

一个“待确认”问题只在它影响用户当前选择的下一步时成为首要问题。其它未完成项留在明确的摘要里，不抢焦点。

| 用户动作 | 缺项的影响 | 预期界面行为 |
| --- | --- | --- |
| 保存设计草案 | 不影响保存 | 允许保存，列出待确认项 |
| 查看已知数量或分支 | 关系未确定时不能算精确值 | 显示已知范围/缺少的前提，不报假精确总数 |
| 生成板图 | 缺组覆盖、载体或映射 | 只阻止本次板图，并指出具体缺项 |
| 执行某项仪器任务 | 缺实际样本、适用方法或必要设置 | 只阻止依赖该项的当前任务，不阻断无关检测 |
| 解释/归一化结果 | 缺方法要求的对照或分析依据 | 可保留原始采集，明确阻止不可靠的派生结论 |

严重程度表达“对当前动作的影响”，不用一个覆盖全实验的红/绿灯。研究设计、执行准备和结果解释各有自己的就绪状态。

## 工具中心：先选任务，再显示相关方法和参数

工具首页按要完成的任务组织，例如“铺板 / 填板”“配液计算”“读板”“成像”“qPCR 采集”“样本交接”。从设计或 Run 打开时，带入用户已确认的检测、样本和组别上下文；不重复问 n，不自动挑选实际样本或仪器。

```text
任务：读取当前检测板
对象：本次检测 / 已选实际板与孔位
输出：终点读数 / 动力学数据（由用户选择）
方法：选择已确认方法版本，或保存待核草案
本次需要确认：该方法和载体要求的读数模式与设置
高级设置：只在当前模式适用时展开

[预览读数任务]  →  核对输入 / 设置 / 待确认项  →  [应用到 Run]
```

参数分四类，而不是一张“设备信息”万能表：

1. 当前动作正确执行所必需的条件。
2. 随目的、样本或输出变化的关键选择。
3. 设备能力约束（例如支持的读数模式或兼容载体）。
4. 实际运行后可获得的设置、文件、时间和读数。

必需不等于手填：可沿用已确认的方法、设备配置或真实元数据。值未提供、来源冲突或不适用于当前任务时显示未知/冲突，不伪装成已读取。方法预设只能减少重复输入，不能替代研究者确认的科学条件或 Run 的实际执行事实。

工具执行返回“建议布局”“计算结果”或“方法参数解析”时带来源、单位和前提；它不是“已经铺板”“已经加样”或“已经测量”的回执。实际动作须由用户确认/执行后记录到 Run。

## Agent 与人的共同契约

工具 API 和 UI 调用相同动作。每个动作定义：

- `purpose`：本动作要完成的任务和输出；
- `input_schema`：明确对象引用、类型、单位和必需条件；
- `purpose_dependent_fields`：何种选择会出现哪些参数、为什么需要；
- `constraints`：方法与设备能力约束、已知兼容性及其来源；
- `output_schema`：预览、计算结果、问题和受影响对象；
- `unknown_policy`：哪些未知值允许草案保存、哪些只阻止当前动作；
- `effect`：只读预览、写入计划、应用到 Run、记录实际执行，四者不可混淆。

Agent 搜索现有方法、读取上下文、生成字段级 proposal、调用 preview、展示差异和待确认值。它不能将猜测升级为事实。会影响 n、对照、终点或样本分配的修改必须让研究者确认；板位计算等确定性结果可在预览后应用。UI 与 Agent 使用同一组校验和来源追踪。

## 三个真实案例的走查判据

### L929 + GelMA 多检测

从记录或一句话建立 CCK-8 与活死检测。组别、独立 n、时间和样本关系未给出的保留待定；不能因为共享浸提材料就推断共用细胞培养单位。样本摘要常驻，兼容/终末关系未确认时不画成确定顺序。D1 的实际事件不能让 D3 显示完成。用户可单独准备已明确的共享材料，不必等待不相关的成像配置。

### SA 铜梯度 + OD / CFU / RNA-seq

用明确的浓度列表或有单位的生成规则批量创建条件；RNA-seq 可只覆盖研究者指定组。历史体积与组别冲突保留原证据和影响，不让公式替用户选真值。OD、CFU 和组学结果有不同测量含义；缺稀释依据时允许保存 CFU 计划，但不能算出可信 CFU/mL。

### 生物膜多分支检测

OD、结晶紫、CFU、RNA 和显微/SEM 等任务分别表达覆盖组、采样时间、材料来源和方法。不同分支并列，只有已确认的材料/步骤依赖才连箭头。测量缺项只阻止受影响的分支；某来源完成一条检测不自动完成其它支路。

验收时让研究者能不借外部纸笔回答：这个读数来自哪一独立来源？哪些检测会用到它？改一组、加一个检测或改时间会影响哪些安排？当前为什么不能生成板图/读数任务？

## 从成熟产品借鉴什么，不照搬什么

- [Opentrons Protocol Designer](https://docs.opentrons.com/protocol-designer/steps/transfer/)：从具体 transfer 任务开始，表单按当前步骤组织输入，并只提供兼容选项；不兼容情况就地说明。Flow rate、tip position 等高级设置按所选操作出现。CellPlanner 可借鉴“任务上下文优先、参数按条件展开”，不照搬机器人独占的甲板模型。
- [Benchling plate maps](https://help.benchling.com/hc/en-us/articles/39943809066637-Create-and-track-samples-with-the-Inventory)：区分可复用的 plate design 与一次实际 plate record。CellPlanner 可借鉴“计划布局”和“实际板记录”分开；不照搬其未完成向导不能保存的限制，因为本产品明确需要可保存草案。
- [NC3Rs Experimental Design Assistant](https://eda.nc3rs.org.uk/EDAfeatures)：结构化设计关系并提供解释决策影响的 feedback。CellPlanner 应把“为什么需要确认样本分配”说清，不只报验证失败；不照搬面向动物研究的全部节点。
- [W3C Forms Tutorial](https://www.w3.org/WAI/tutorials/forms/)：字段按任务分组、清晰标记并说明如何纠正错误，支持减少重复输入；动态显隐不能使复杂关系不可发现。
- [GOV.UK checkbox guidance](https://design-system.service.gov.uk/components/checkboxes/)：条件展开适合少量后续输入，不适合将复杂样本关系藏在一次勾选后。流向图应是可见入口、有摘要、有返回路径的独立编辑，不是突然插入大块表单。

## 两种主视图的比较与当前建议

| 候选 | 优点 | 风险 | 案例表现 |
| --- | --- | --- | --- |
| A：组 × 检测矩阵 | 覆盖缺口、部分组检测、批量修改一眼可见 | 多时间点塞进格子会膨胀；移动端宽；来源关系无法只靠格子表达 | SA 梯度和生物膜部分覆盖很清楚；L929 可压成小矩阵 |
| B：每个检测一张卡 | 时间、方法、样本摘要自然放在一起；手机易读 | 跨检测比较覆盖时要来回看；许多组会变成重复标签；差异不明显 | L929 简洁；SA 与生物膜难快速发现某些组漏测或不适用 |

**当前较稳的候选是 A+B 混合，而非选一方：**宽屏默认组 × 检测矩阵，时间放在各检测标题；所有组都共用同一时间安排时只显示一次，个别组例外才在格子标记。矩阵不展开为第三维。手机将同一数据改排为逐检测卡片，组覆盖变成可读标签；不是另一份数据或另一套编辑流程。

每个单元必须区分“做 / 不做 / 未决定”。没有选择不能被系统默认为“不做”。批量时间或覆盖变更显示明确影响范围，保留用户逐格设置的例外。样本关系摘要常驻；分支、终末、顺序使用、混样或来源冲突时给清晰的“查看样本去向”入口。

用当前三个案例推演，混合视图是最值得先验证的：L929 只有少数组别与两项检测，矩阵不挤；SA 梯度要快速比较检测是否覆盖所有组，矩阵优于独立卡片；生物膜多检测需要同时看到覆盖矩阵和来源分支，卡片能呈现各检测的时间/样本摘要，但不能替代分流图。

**暂时收敛：**单一设计对象；一句话/导入/复制/手动同入口；同页画布；组 × 检测两维覆盖；每项检测拥有自己的时间；样本关系摘要常驻、复杂关系按需展开；“工具”独立且按任务组织；预览与实际写入分开；草案保存与当前动作就绪分开。

**先不要冻结：**宽屏矩阵的密度阈值、手机交互细节、哪些来源关系可被判为简单摘要、哪些特定参数被认定为动作必需、冻结一个 Run 时允许只包含部分未来检测。以上需通过可用性任务观察验证。

## UI 消融评估：验证删改一个版块会发生什么

这里借用消融实验的思路，但称为**可用性消融比较**：控制任务内容与底层数据不变，只移除或重排一个界面组成，观察是否影响正确理解和完成操作。它是产品评估方法，不是科学实验或已有实测结论。

### 比较顺序

1. **整体流程基线**：当前四段式新建设计表单；与同一内容、同一保存能力下的单页设计画布比较。此阶段只判断“填完一份草案”是否更快、更清楚，不据此归因到某个组件。
2. **组件消融**：固定使用画布，逐轮只改变一个因素；矩阵/检测卡、样本关系摘要、简短的当前待确认项、流向小图、工具入口各自独立比较。每轮不得同时删摘要、改字段、换命名和改业务校验。
3. **组合复测**：将单项看起来有效的组成组合起来，再走完整的多检测任务，以确认它们互相没有造成新歧义。

| 因素 | 完整画布 | 消融变体 | 主要观察 |
| --- | --- | --- | --- |
| 覆盖关系 | 组 × 检测矩阵 | 检测卡视图 | 能否迅速发现某组未测、明确不做或仍待决定 |
| 样本关系 | 常驻短摘要 + 按需流向图 | 只有“查看详情”入口 | 是否把共享材料误当共享实验单位；能否解释读数来源 |
| 当前待确认 | 一项最高影响问题 + 其余摘要 | 只显示全部待办列表 | 是否知道先处理什么；是否误以为其它项目阻塞当前任务 |
| 关系可视化 | 来源→分样→检测的小图 | 等价短文本 | 读者能否指出分支、终末用途和未确定关系 |
| 工具入口 | 按任务找工具，带入已知上下文 | 按设备类型进入 | 能否找到铺板/读数操作；是否被无关参数淹没 |

“完整”是候选主方案，不代表一定更好。比如样本图可能增加扫读负担；只有观察到它减少关键来源错误时才保留。矩阵和卡片是布局对照，覆盖关系必须保持完全相同。

### 桌面走查的预判（不是用户测试结果）

- **不应删除**：未决定/不做/已决定的区分；来源与实验单位摘要；草案保存；计划值与执行事实的标签。这些不只是装饰，它们避免科学关系被界面压扁。
- **适合做消融**：完整样本流向大图（简单案例可以先隐藏）、首屏所有待办（可改成一项优先问题 + 完整列表入口）、重复展示的检测参数和文字说明、未选工具时的仪器高级参数。
- **应重点比较**：组×检测矩阵与检测卡；样本摘要的常驻程度；工具首页按任务还是按设备分组。
- **暂定推演**：SA 部分组测序和梯度处理会从矩阵受益；L929 需要检测卡式的时间/样本短摘要；生物膜多分支需要能展开的流向图。因此矩阵 + 检测列摘要比单独矩阵或单独卡片更稳，但这仍是设计推演，必须通过实际使用者验证。
- **工具导航**：首页按任务组织（铺板、填板、读板、成像、qPCR、样本交接），同时允许搜索仪器名或按设备筛选。完全按仪器分类容易让用户先猜“要找什么设备”；只按任务而无法搜设备名也会让熟悉仪器的用户绕路。

### 固定任务与正确答案

不同界面版本使用同一组事实和约束；任务说明给目标，不提示点击路径。每轮最多给参与者 3–5 个任务，任务顺序交错，避免把后一版的学习收益误当成界面优势。先用纸面/静态原型做观察，再决定是否实现高保真版本。

- **起草**：用 L929 + GelMA 建一个 CCK-8 与活死检测设计；保留未给出的组别、n、时间与复用关系为未知；保存草案。
- **部分覆盖与冲突**：用 SA 梯度案例，让 RNA-seq 只覆盖指定组；指出记录冲突仍未解决，不能自动选一个数值。
- **样本分支**：用生物膜多检测案例解释一个 CFU 或图像结果来自哪里、是否从同一来源分样、哪些关系还待确认；不能把不同测量强行排成同一条顺序。
- **调用工具**：从当前检测启动一个读板或铺板任务；确认它继承了哪些设计上下文、还缺什么、预览结果是否被误当成已经执行。
- **泛化检查**：另选 qPCR、流式、组织成像、动物纵向或组学交接中的一类，检查界面没有假设所有对象都是孔、也没有要求所有设备字段都填写。

同一个人不应简单地先后用两版完成完全相同的数据：学习效应会偏向第二版。可给相近但不同的案例、对调版本顺序；如果只用一两位内部评审者，结果应称为走查发现，不声称统计结论。

### 结果怎么判

首要指标是**正确完成**，速度排在其后。每项任务记录：

- 是否完成，以及是否误把未决定当成不做；
- 关键理解错误数：例如把材料共用等同培养单位共用、把孔/视野当成独立 n、把计划板图当成实际已铺板；
- 能否正确指出当前阻断条件及它影响的动作；
- 完成时间、回退次数和用户主动求助次数；
- 任务后“容易程度”和“答案有把握程度”的简短评分。

预先规定严重错误高于平均耗时和主观偏好：若一版更快，却增加了样本来源或 n 的关键误读，不能判为胜出。一个板块只有在不损害正确性、可发现性或信心的情况下，才适合被删除；若视觉简化让人忽略必须确认的关系，应调整摘要位置，而非隐藏语义。

[GOV.UK usability benchmarking](https://www.gov.uk/service-manual/measuring-success/usability-benchmarking-a-website-or-whole-service)建议用清晰任务测完成、耗时、放弃/误判，并避免给参与者过多任务；[OHID 的定性可用性测试指南](https://www.gov.uk/guidance/usability-testing-qualitative-studies)强调清晰成功标准、观察真实或可能使用者，并指出小规模定性测试用于发现常见问题，不能替代大样本量化评估。任务顺序也可能产生学习迁移，应交错或对调版本顺序；[任务序列效应研究](https://www.iadisportal.org/digital-library/task-sequence-effects-in-usability-tests)提醒顺序会影响成功率、耗时及主观评价。

如果第一轮只有主人自己走查，能发现表单断点和明显误导，但不能据此宣称“用户效率提高”。要比较效率，至少需要邀请实际设计者/执行者完成同一组标准任务；定量显著性则需要另行估算参与人数和测试功效。

验证方法：让 5 名实际使用者（若无法招到足量，至少逐位记录）分别完成三个案例中的“从不完整意图保存、编辑检测覆盖、确认一个样本分支、调用一个工具预览”任务；记录首次停顿、误把空白理解为不做、把共用材料误解为共用样本、把技术重复当独立 n、是否需要纸笔。随后比较矩阵优先版和检测卡优先版，不以“页面更少”作为成功标准。
