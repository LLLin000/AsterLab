# Plan → Session → Results:双场景走查

- 日期:2026-11-07
- 状态:本地浏览器走查;不是用户测试
- 场景 A:L929 + GelMA/ZnO 浸提液,CCK-8 与 LIVE/DEAD,D1/D3/D7
- 场景 B:Western blot 11 步

## 结论

当前已经有 Plan / Session / Results 三个内部状态,但没有新增第五个主标签:

- **Plan**:设计摘要按检测分行,显示每组时间点和时间点关系;编辑器可编辑全部检测,不再只处理 `assays[0]`。
- **Session**:Run 北京时间点筛选任务;默认落到未完成时间点;确认按任务进行;阻塞检查门禁;冻结资源。
- **Results**:Run 内部标签,展示所有执行事件、读数/测量数量、检查数量和“已完成但无读数”的任务。

## 场景 A:L929 多检测跨天

### 已走通

1. Design 摘要显示:
   - CCK-8 · D1/D3/D7 · 同一实体样本重复 · OD450 · Protocol
   - LIVE/DEAD · D1/D3/D7 · 每时间点独立样本 · 图像终点 · Protocol
2. 编辑器显示 2 个检测卡,可分别编辑名称、终点、方法、单位、时间点、时间点关系、对照。
3. Run 显示 D1 / D3 / D7 时间点条;每个时间点 3 个任务:CCK-8 read、Stain LIVE/DEAD、Image。
4. 当前任务在 D1 内前进;D1 全部完成后才进入 D3,不再从 CCK-8 D1 直接跳到 CCK-8 D3。
5. Run 顶部 project/design 上下文会同步到当前 Run,不再出现打开 L929 Run 却显示 Western blot 项目。

### 仍缺

- L929 演示项目没有绑定 View,Session 的三块材料/仪器/检查显示“未绑定”;Plan 摘要能看,但执行页没有可核对材料。
- 设计只有组别和时间点,没有逐孔 Sample ID;`PlannedTask.target` 仍是 `Unresolved`。
- 没有实验前“需要准备什么”的汇总;资源需求仍依赖后续 View/Protocol。
- 结果只能查看,不能批量粘贴/导入 OD 或 Cq。

## 场景 B:Western blot

### 已走通

1. 11 个任务按步骤显示;默认停在未完成步骤。
2. 阻塞检查未记录时确认按钮禁用;记录通过后进入下一步。
3. 完成事件自动写时间;不要求备注/操作人。
4. Run 创建时锁定当前 View id,并把材料/仪器/检查表冻结到 `execution_resources`。
5. 完成态 11/11 只读;顶部显示“全部任务已完成”。
6. Results 标签列出所有事件;可看到完成但无读数的任务。

### 仍缺

- ECL 成像没有图片关联入口;Results 只能显示已有事件。
- 操作完成与结果完整仍未由步骤级“必需结果”契约驱动;当前用“无读数”提示,不判断是否必需。
- 结果录入仍是只读汇总。

## 逐行视觉走查反馈

第一轮子代理使用整页截图和 `innerText` 汇总，漏掉了只在一个视口里出现的细节。第二轮改为:视口截图、只抽取当前视口内按 y/x 排序的可见块、每次滚动约 600px、逐行阅读后再点击下一个控件。第二轮发现:

- 390px 下第三个任务 chip 从 x=374 开始,右半部分在视口外;整页截图只显示“没有文档溢出”。
- 阻塞检查的禁用状态和检查控件在首屏下方,整页阅读容易把它当成“确认按钮可用”。
- `时间范围：per_timepoint` 直接显示内部枚举值。
- L929 当前任务仍显示 `D1/D3/D7`,而不是当前 D1。
- 打开 Run URL 未带 project/design 时,顶部项目上下文可能与 Run 不一致。

另一个只在这个方法下暴露的严重问题:Run 页顶部仍渲染了设计工作区和“此 View 还没有工作流节点”。原因是 `.workspace/.detail` 的 `display:flex` 覆盖了 HTML `hidden`;已加全局 `[hidden]{display:none!important}`。

已修:任务/时间点少于等于 4 个时换行;时间范围本地化;目标时间点改为当前任务时间点;Run 上下文同步;Results 与执行安排切换时只显示一个区域;设计编辑器保存条改为底部粘性。

## 2026-11-08 追加

- **混合时间范围**:Run 任务条分为“通用准备”和当前时间点任务;不会再隐藏 `timepoint=null` 的一次性步骤。`pages-smoke` 已加入负例:1 个准备步骤 + 2 个时间点步骤,首屏显示通用准备与 24 h/48 h,任务总数 3。
- **状态原子化**:执行事件插入与 Run 状态刷新在同一事务内完成;测量事件不会把已完成任务改回未完成。
- **结果录入**:Results 内增加每行“值, 样本编号”的批量粘贴,写入 `measurement` 事件;不改变操作完成状态。
- **实验前准备**:Run 顶部增加“准备清单”,汇总冻结材料和仪器;无冻结资源时明确显示 0 和 Protocol 列表。
- **目标措辞**:`PlannedTask.target` 仍是 `Unresolved` 时显示“适用:组别 · 时间点”,不再把组别称为“目标样本”。

验证:L929 Run 首屏显示 5 个任务(2 个通用准备 + 3 个 D1 任务),完成 Seed 后进入 Apply extracts;Run 状态为 `in_progress`;结果页可粘贴两行读数并生成 measurement 事件。
