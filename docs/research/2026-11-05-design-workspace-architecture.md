# AsterLab 前端架构:设计工作区与共用词表

- 日期:2026-11-05
- 状态:架构提案;**当前暂停实施**。K0/K1 知识基础审查通过前,不得据此修改 Slint 或新增全屏编辑器;实施计划以 [implementation-plan](../implementation-plan.md) 的 P4-Knowledge Foundation 为准。
- 基线:仓库 HEAD;现有 `AppWindow.slint` 的四区域壳、设计 / 准备 / 执行三种模式、右侧检查器。
- 目的:修正“新建设计”被做成一个脱离现有版面的全屏弹层的问题。实验设计不是第 5 个孤立面板,而是设计模式内部的工作状态。

## 1. 结论

整个应用保留 **4 个常驻区域**,设计模式内部有 **浏览** 与 **草稿** 两种状态;草稿状态由实验设计触发,并重排中间工作区和右侧面板,而不是新开一个全屏页面。

| 常驻区域 | 位置 | 职责 |
| --- | --- | --- |
| 上下文栏 | 顶部 56px | 项目 → 设计 → 运行的面包屑;设计 / 准备 / 执行模式切换;草稿状态、保存、取消 |
| 导航栏 | 左侧 216px | 项目、实验设计、运行批次;新建 / 编辑设计入口;有未保存草稿时做离开确认 |
| 工作区 | 中间自适应 | 浏览态显示地图 / 结构 / 证据;草稿态显示 4 步设计流程 |
| 上下文面板 | 右侧 304px | 浏览态是选中对象的检查器;草稿态是实时设计摘要、待确认项和保存状态 |

**实验设计不是一个独立面板。** 它把中间工作区从“浏览态”切到“草稿态”,并把右侧检查器切到“设计摘要”。左侧导航和顶部上下文始终保留,研究者不会丢失当前项目、设计或运行上下文。

## 2. 面板与状态

### 2.1 浏览态(Design:Browse)

中间工作区顶部是设计标题、目的、计数、实验单位,以及一个视图切换:

| 视图 | 中间工作区内容 | 右侧上下文面板 |
| --- | --- | --- |
| 地图 | 实验地图、组别 × 检测关系、时间点、样本关系、待确认项 | 选中组别 / 检测 / 字段的只读详情 |
| 结构 | 组别列表、检测列表、样本分配摘要 | 选中对象详情;底部“编辑此设计” |
| 证据 | 来源、冲突、只读完整性检查 | 选中证据 / 冲突详情 |

- 点击地图节点或结构行,只改变右侧上下文,不切页。
- “编辑此设计”进入草稿态,从第 1 步开始;不复制设计,不新建草稿记录。
- 浏览态仍只读;任何字段都不能在检查器里直接改。

### 2.2 草稿态(Design:Draft)

中间工作区顶部是 4 步流程条:

```text
1 研究问题  →  2 组别  →  3 检测  →  4 关系与检查
```

| 步骤 | 中间工作区 | 主要交互 | 右侧面板 |
| --- | --- | --- | --- |
| 1 研究问题 | 设计名称、目的、实验单位、主要比较 | 名称 / 目的自由文本;实验单位和主要比较用选项 | 实时摘要:组数、检测数、未完成项 |
| 2 组别 | 组别卡片列表;每张卡有组名、角色、处理条件、独立 n、技术重复 | 角色、条件、n、技术重复全部用选项;“添加组别”从模板开始 | 选中组的摘要;条件词表入口 |
| 3 检测 | 检测卡片列表;每张卡有检测名、方法、指标、单位、时间点、时间关系 | 方法优先;指标和单位跟随方法给出默认选项;时间点用多选;检测名自由文本 | 实时关系图预览;方法 / 指标来源 |
| 4 关系与检查 | 组别 × 检测覆盖、样本关系、Protocol 状态、待确认项 | 只做确认和局部修正;不在这里重新填整张表 | 保存前检查、未解决项、保存 / 取消 |

- 步骤条不是新页面;草稿对象只有一个,切换步骤不丢失输入。
- 保存失败留在草稿态,错误显示在顶部或右侧;保存成功回到浏览态,选中刚保存的设计。
- 取消 / 切换设计 / 切换模式时,若有未保存修改,弹出三选一:保存、放弃、返回。
- 草稿态下“准备”“执行”模式仍可见,但切换时走同一个未保存检查。

### 2.3 设计模式的版面变化

```text
┌──────────────────────────────────────────────────────────────┐
│ 上下文栏:项目 › 设计 › 运行   设计 | 准备 | 执行   草稿 · 未保存 │
├──────────┬───────────────────────────────────┬───────────────┤
│ 导航栏    │ 工作区                             │ 上下文面板     │
│ 项目      │                                   │               │
│ 设计      │ 浏览态:地图 / 结构 / 证据           │ 选中对象详情   │
│ 运行      │ 草稿态:4 步流程 + 当前步骤内容      │ 或设计摘要     │
│          │                                   │               │
└──────────┴───────────────────────────────────┴───────────────┘
```

- 顶部上下文栏始终显示当前项目、设计和运行;草稿态增加“草稿 · 未保存”状态,不把标题改成“新建实验设计”。
- 左栏在草稿态保留;它是上下文导航,不是编辑器的一部分。
- 右侧面板宽 304px,避免草稿态再挤成表单;当前步骤的字段在中间,摘要和检查在右侧。

## 3. 词表架构:共用、可复用、独特

### 3.1 三类词

| 类别 | 例子 | 处理方式 |
| --- | --- | --- |
| 全局共用词 | 实验单位、组角色、独立 n、技术重复、时间关系、容器类型、常见方法、常见指标、单位 | 代码内置受控词表;只能选,不能自由输入 |
| 项目 / 团队词 | 具体处理条件、材料名称、细胞系、检测名称、Protocol 版本、仪器 | 从项目已有设计中派生,选择优先;新词只定义一次,之后进入词表 |
| 设计独有词 | 研究目的、设计标题、一次性备注 | 自由文本;不进入词表,不参与自动推断 |

判断规则:

- 这个值会被报告、统计、Agent 读取或跨设计比较吗?会 → 受控词或引用。
- 这个值只描述本次研究意图吗?是 → 自由文本。
- 这个值在别的设计里可能重复出现吗?会 → 项目词表。
- 这个值是否必须带数值和单位?是 → 结构化字段(值 + 单位),不是一段字符串。

### 3.2 选项优先的字段

| 字段 | 选项来源 | 独特值怎么处理 |
| --- | --- | --- |
| 实验单位 | 内置:独立培养孔、独立玻片、独立切片、独立视野、独立动物、独立样本 | 内置没有时用“新建实验单位”;创建一次后进入项目词表 |
| 组角色 | 内置:空白对照、载体对照、阳性对照、处理组、标准品组 | 不允许自由输入;不确定用“待确认” |
| 独立 n / 技术重复 | 内置:待确认、1–12 | 只选整数;不在选项里的数值用“自定义数值”,存为整数并校验 |
| 处理条件 | 项目词表:已有条件 + 内置类别(空白、载体、材料、药物) | “选择已有”或“新建条件”;新建时填类别 + 名称,之后可复用 |
| 检测方法 | 内置常用方法 + 项目已有方法 | 新方法只定义一次;方法决定默认指标 / 单位 |
| 测量指标 | 按方法给出候选 + 项目已有指标 | 新指标只定义一次;与方法的对应关系保留为“研究者选择” |
| 单位 | 内置单位词表 | 不允许自由文本;不在词表时走“新建单位” |
| 时间点 | 内置 D0/D1/D3/D7/D14/D21/D28、4h/6h/24h/48h/72h + 项目已有 | 多选;新时间点用“值 + 单位”创建,之后复用 |
| 时间关系 | 内置:各时间点独立样本、同一实验单位重复测量、待确认 | 不允许自由输入 |
| 检测名称 | 项目已有检测名 + 内置检测族 | 新名称只定义一次;名称不是方法,不能代替方法 |

### 3.3 “选择或新建”模式

所有受控字段统一用同一个交互,不出现“空白输入框 + 用户从头写”:

1. 下拉第一项是“选择已有”或“待确认”。
2. 最后一项是“新建…”。
3. 选“新建…”后,在当前卡片内展开一个最小表单:类型(固定)+ 名称(短文本)+ 必要的数值/单位。
4. 保存后立即选中新值,并写入项目词表;下一次下拉就能选到。
5. 只有“设计独有词”保留普通文本框。

新建词必须有稳定的 key 和显示名;不能把显示名当 key。当前版本没有独立词表表,先由读模型中的已有设计派生项目词表;这是过渡实现,不是最终数据模型。

### 3.4 方法驱动的默认值

参考 Opentrons 的依赖选项:先选仪器/耗材,再只显示兼容的吸头、量程和步骤。AsterLab 同理:

- 先选检测方法,再显示该方法常用的指标、单位、时间点。
- 默认值只是建议,不是事实;用户改过之后保留“与建议不同”的状态,不静默覆盖。
- 方法或指标变化时,不自动改写已输入的时间点、n 或样本关系。

## 4. 外部产品参考

这些产品把“结构化字段 + 受控词表 + 可复用实体”做在实验设计 / 记录流程里,不是让用户从空白文本开始:

- **Benchling Registry schemas**:字段类型包含 Dropdown、Entity、Inventory Link、Entry 等;Dropdown 是可复用的受控词表,集中维护,跨 schema 更新。来源:[Configure Registry schemas](https://help.benchling.com/hc/en-us/articles/39935326052493-Configure-Registry-schemas)。
- **Benchling Data Modeling best practices**:明确建议用 dropdown 统一数据、减少自由文本错误;材料用 Registry / Inventory 引用,而不是每次重写名称。来源:[Best Practices - Data Modeling & Discovery](https://help.benchling.com/hc/en-us/article_attachments/16053452937869)。
- **Labguru form-like experiments**:表单元件包含 Collection(下拉)、Select box、Equipment(仪器下拉)、Inventory item 等;Protocol 可预置表单并按 section 复用。来源:[How to Create Form-like Experiments](https://help.labguru.com/en/articles/1492329-how-to-create-form-like-experiments)。
- **SciNote Fillable Forms**:表单块包含 Number(带单位/校验)、Single/Multi choice、Inventory Item;表单嵌入 Protocol Step,发布后复用。来源:[How to build and use a Fillable Form in SciNote](https://knowledgebase.scinote.net/en/knowledge/how-to-create-a-form)。
- **Opentrons Protocol Designer**:先选 pipette / labware,再只显示兼容的 tip rack、path、liquid class 和步骤参数;选项是依赖式的。来源:[Transfer steps](https://docs.opentrons.com/protocol-designer/steps/transfer/)、[Starting Deck](https://docs.opentrons.com/protocol-designer/starting-deck/)。

共同模式:

1. **字段是结构化控件,不是一张空白表格**:dropdown、number + unit、entity link、multi-choice。
2. **词表集中维护**:改一次选项,所有引用处同步。
3. **实体引用优先于文本**:材料、仪器、库存、Protocol 用引用;文本只用于名称和说明。
4. **依赖选项**:先选大类,再只显示兼容的小类。
5. **模板复用**:步骤 / 表单 / Protocol 从已有模板插入,不从零写。

## 5. 当前实现与缺口

| 现状 | 架构要求 | 处理 |
| --- | --- | --- |
| “新建设计”打开全屏 `DesignEditorView` 覆盖层 | 设计是工作区的一种状态,不是全局弹层 | 移除全局覆盖层;把编辑内容放进中间工作区,右侧改为摘要 |
| 组角色 / n / 技术重复是 LineEdit | 受控选项 | 改为 ComboBox;n / 技术重复用整数选项 |
| 处理条件、方法、指标是 LineEdit | 选择已有 + 新建一次 | 读模型派生项目词表;ComboBox + 内联新建 |
| 时间点是一个逗号分隔字符串 | 多选 + 结构化时间点 | CheckBox / 多选;自定义时间点用值 + 单位 |
| 检测没有单位、时间关系、Protocol 引用编辑 | 受控字段 | 增加单位、时间关系、Protocol 选择;未引用保持“待确认” |
| 独立 n 可自由输入任意文本 | 整数或待确认 | 选项 + 自定义数值校验;不把技术重复当独立 n |
| 不同设计的条件 / 方法无法复用 | 项目词表 | 先从 `model.designs` 派生;后续加项目词表记录 |

### 已知数据模型缺口

- 处理条件目前是单个 `condition` 字符串,无法表达“材料 + 浓度 + 单位”。架构要求结构化条件;在数据模型未改前,UI 只能做“类别 + 名称文本”,不能假装浓度已结构化。
- 材料 / 仪器 / Protocol 没有统一的实体引用;当前只能用名称和现有 ID。不要把名称匹配当成实体关联。
- 项目词表没有独立存储;过渡版从已有设计派生,删除最后一个引用会丢失该词。正式版需要项目级词表记录。

## 6. 实施顺序

1. 把 `DesignEditorView` 从全局覆盖层改为工作区组件;保留四区域壳。
2. 设计模式增加浏览态 / 草稿态状态机与未保存离开确认。
3. 浏览态拆成地图 / 结构 / 证据三个视图;右侧检查器沿用。
4. 草稿态实现 4 步流程;先接已有字段,再接受控词表。
5. 加入统一 `OptionPicker`(选择已有 / 待确认 / 新建一次)和项目词表派生。
6. 方法驱动的默认指标 / 单位 / 时间点;保留“与建议不同”状态。
7. 保存后回浏览态;错误留在草稿态;不伪造保存成功。

## 7. 验收

- 新建设计不再出现脱离导航和上下文的全屏页面。
- 从浏览态进入编辑、切换步骤、取消、保存,左侧项目和设计上下文不丢失。
- 草稿未保存时切换设计 / 模式 / 项目有明确确认。
- 组角色、n、技术重复、时间关系、单位只能从选项选择。
- 处理条件、方法、指标、时间点优先从已有值选择;新建值只定义一次并在下一次出现。
- 修改方法不会静默覆盖已有指标、时间点或样本关系。
- 未知值保持“待确认”,不被写成 0、空字符串或推断值。
- 390px 宽度下,步骤条和卡片不横向溢出;保存 / 取消仍可达。

## 8. 本轮不做

- 不新增数据库表、迁移或词表 API;过渡版只从读模型派生。
- 不重写 Protocol / Run 工作区;先修设计模式的面板和词表。
- 不引入新的前端框架、图标库或动效系统。
- 不把“实验设计”做成独立一级页面或全屏弹层。
