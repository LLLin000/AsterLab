| Dimension | Verdict | Strongest evidence |
|---|---|---|
| Product logic | **Page roles overlap; one surface is unreachable** | Protocol is not a page (`internal/shell/shell.go:115`), only a Tools tab (`main.go:1761`); Notebook and Run both present run history |

The important distinction from the brief holds: passing tests and registered
modules are not product usability or platform extensibility.

## 2. Product decisions (binding via `ux-contract.md`)

1. **Protocol becomes the sixth surface**, read-only. It never gains edits.
2. **Notebook is prose-only.** Run gains a `history` tab over the same
   authoritative events; Notebook's timeline is removed, not duplicated.
3. **Tools keeps its page and gains a Run-task handoff**; drafts persist for the
   session.
4. **Project workspace removes the 6-item design cap**
   (`internal/shell/shell.go:331-337`).
5. **Design inspector is persistent at ≥1100px**, a bottom sheet below.
6. **Run puts recording first** at ≤900px; two columns at ≥1360px.
7. **Protocol never conflates frozen with preview.** A Run-backed document shows
   `已冻结` + Run id + frozen revision; a design-only projection shows `预览` +
   design revision and is not exportable as a frozen record (`ux-contract.md` §1.1).
8. **Notebook prose may cite facts, never create them.** Event, file and
   measurement references must resolve to the authoritative record
   (`ux-contract.md` §1.2).
9. **Tools sends drafts, not facts.** "Send to current Run task" produces an
   unconfirmed draft; the write happens only after operator confirmation in Run,
   through the same Core command as manual entry (`ux-contract.md` §1.3).

## 3. SDK decisions

1. Keep `spec/modules.json` as the single contract; do not invent a second
   registry.
2. Freeze now: fence envelope, Foundation port types, UCUM subset, typed
   references, diagnostic shape, `step@N` semantics, renderer-key rule.
3. Version, never retrofit: breaking field meaning → new `schema`; renderer key
   shared only when interaction semantics are identical.
4. Do **not** promise a plugin ABI. State plainly that v1 modules are compiled
   in, and make the *contract* the stable surface.
5. The three probe classes stay the acceptance tests for any future
   "extensibility" claim: a new calculator, a new record+display, a new
   artifact-backed module. A claim without one of these shipped is marketing.

### Wave 3 — SDK Owner (serial)

Status: **partly complete**. Shipped: `sdk.validate`, an explicit
`ASTERDOC_RULES` registry checked at startup, one shared Go/Rust parity fixture
(9 samples, both sides), and editable `string[]` fields in the generic editor.
Not shipped: `renderers.static` (a real static renderer per module, not a flag)
and editable `object-list` rows. Both stay on the backlog and are not claimed.

The `string[]` work also fixed a latent bug: composite ports received an empty
scalar draft, so a plain save wrote `""` over a plate's `groups` or a step's
`tasks`.

1. `sdk validate` CLI over `validate_asterdoc_spec` + source validation +
   compile attempt.
2. Composite-field editing in `GenericModuleEditor` (`internal/asterdoc/view.go:867-1012`).
3. `renderers.static` end-to-end via `StaticPreview`.
4. One shared fixture consumed by both Go and Rust parity tests.
5. Replace the hand-written Rust rule match with an **explicit registry of known
   validators**: a rule name must be registered in both languages, and an
   unknown rule is still rejected. Data-driving rule names from the manifest is
   rejected as a design: it would silently accept unknown rules.

### Wave 4 — one real module, then integration acceptance

Status: **module shipped**. `rna_reagent_usage@1` is a derived calculator:

`stock = (target/stock) × total`, `diluent = total − stock`, all in the authored
volume unit. It renders through the generic editor in Design and the shared
read-only summary in Run, both labelled 派生值.

Two defects the shared fixture caught during integration, both fixed here:

1. The module's rule existed in the manifest and in Rust but not in Go's

2. The agent replaced two existing parity fixtures instead of adding to them,
   silently dropping instrument-profile coverage. Restored.

`object-list` editing and `renderers.static` remain unshipped.

## 5. Hard gates (from the brief)

- **Environment gate:** no parallel worktree builds or large E2E while D: free
  space is inadequate; no unreviewed recursive deletion; real SQLite databases,
  source, uncommitted changes and signing material are never deleted.
- A UX slice is not accepted without 1360×880 and 900×600 screenshots of the
  real window and the §6 checklist in `ux-contract.md`.
- An SDK slice is not accepted unless a new module is usable from Design,
  Protocol, Run, Notebook and CLI, and old frozen Runs still read.
- No slice may change Core transaction logic to serve a display-only module.
- No slice edits a file owned by another owner (`ownership.md` §3).

## 6. Deliberately not doing yet

- No RC-4/RC-5 feature push.
- No bulk migration of existing pages.
- No plugin ABI, template market, or device control.
- No global `cargo fmt` (the tree is not rustfmt-clean; a bulk reformat would
  bury the review diff).
