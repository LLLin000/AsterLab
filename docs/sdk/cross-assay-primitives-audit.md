# 跨实验类型压力审计与五大通用原语

- 上游基线：`docs/sdk/huvec-tube-formation-case/DESIGN.md`、`UI-REDESIGN.md`、`docs/sdk/rna-extraction-case/REPORT.md`
- 目的：用 **HUVEC 成管**、**复杂 RT-qPCR**、**小鼠体内给药+终点组织分流（含 WB 对照）** 三类异质湿实验反推系统盲区，将“按实验打补丁”收敛为 **5 个通用底层原语**。

---

## 一、三类实验对照矩阵

| 维度 | HUVEC 成管（细胞+水凝胶+显微图） | 复杂 RT-qPCR（RNA提取+QC+反转录+qPCR） | 小鼠体内药效 + 终点分流（+WB 对照） |
|---|---|---|---|
| **实验单元** | 12 孔板孔位（`A1..C3`） | 样本管 → 96/384 孔板交叉位 | 活体动物/笼位 → 切分后的多份组织 |
| **容器拓扑** | 2D 孔板（1 孔 = 1 样本） | 离心柱/管 → **2D `样本×基因×复孔+NTC`** | 动物笼位 → **一对多组织拆分**（WB：1D 泳道+剪膜） |
| **配液与计算** | 设计期固定配方（按孔算总用量） | **运行期动态配平**（测 Nanodrop 后逐管算加样量） | 按体重实时算给药体积（`mg/kg`） |
| **时间结构** | 45m 短循环 + 2h 空窗 + `t0+6/12/24h` | 半日连续 + 13 子步折叠 + 40 循环热程序 | **跨周日历**（D0/D3/D6…重复给药与量瘤） |
| **运行期分支** | 无气泡按规则跳过离心 | **QC 门控**（低浓/污染样本单管剔除或重提） | **中途死亡脱落（Censoring）** + **Run 期盲法遮罩** |
| **核心事实产出** | 162 张显微图 + 实测固化秒数 | Ct 原始 CSV 批映射 + $\Delta\Delta C_t$ | 纵向瘤体积/体重曲线 + 跨 Run 下游血缘 |

## 二、新增暴露的 7 个具体缺口（RT-qPCR + 体内/WB）

1. **运行期动态计算器缺位**：Design 只写得出公式骨架（如统一 1 µg 上样、按 kg 体重给药），**Run 必须能读取前一步实测值现场生成“逐样本/逐鼠加样表”**。
2. **步内单样本状态与局部剔除缺位**：目前 `PlannedTask` 只有任务级状态；RT-qPCR 的污染样本剔除、小鼠中途死亡退出，需要 **步内单样本状态（Active / Dropped_QC / Censored / Rework）**，防止阻塞整轮 Run 或下游强制报错。
3. **二维交叉板与非孔板容器缺位**：`plate@1` 缺少 `Sample × TargetGene × WellRole(Unknown|NTC|Standard)` 交叉映射；同时容器模型不能写死 2D 圆孔，需兼容 **1D 泳道（WB）**、**物理裁剪拆分（剪膜/切瘤）** 与 **动物笼位**。
4. **多层级子流程的折叠执行**：`01 RNA 提取` 展开 10 个子步时，手机/桌面左侧轨必须支持父步骤折叠汇总（如 `01 RNA提取 6/10`），避免平铺撑爆导航。
5. **跨周重复日程缺位**：21 天给药量瘤不能画成 80 个串联节点，Run 需要基于周期日程的 **“今日待办队列（Today's Agenda）”** 视角。
6. **Run 期盲法遮罩 ↔ Record 揭盲关联**：实验员在 Run 量瘤/评分时必须能屏蔽分组（只见 `Cage-2 / #05`），而 Record/Notebook 统一按冻结分组揭盲渲染。
7. **跨 Run 样本一对多物理分叉血缘**：一块肿瘤分成福尔马林/RNA/蛋白分别进入 3 个独立下游 Run，需要全局 `Sample → Aliquot` 血缘连接上游取材事实与下游测量结果。

## 三、收敛为 5 个通用底层原语

1. **样本状态机与跨 Run 分叉血缘**（单样本剔除/脱落 + `ParentSample → Aliquot` 跨实验溯源）
2. **运行期动态计算器**（`Read上游实测 → Compute逐样本配方 → Dispense加样表`）
3. **通用容器拓扑**（2D 交叉矩阵板 / 1D 泳道 / 笼位 / 支持物理 Split）
4. **分层与周期调度**（父子步骤折叠 + 短时计时器 Timer + 跨周今日日程）
5. **视角可见性控制**（Run 盲法遮罩 ↔ `RecordProjection` 揭盲汇总）

## 四、外部成熟工具反查补漏与「精简不臃肿」边界原则

对照 **protocols.io**、**Benchling**、**SciNote**、**Labguru**、**eLabFTW** 的成熟路径后，补齐 5 条不破坏“轻量工作台”边界的设计收敛：

1. **独立且非强制的「储藏室（Pantry）」台账**：记录名称、存放位置、购入/开封日期、保质期与状态；**Design 期零强制**（只写理论配方），**Run 期一键可选关联**（带入批号/效期/细胞代次，不选绝不阻断实验）。桌面端由现有冗余的 `资料与工具` 演进承接，不增加顶栏膨胀。
2. **物理贴标与扫码完全插件化**：主程序不内置打印机驱动或扫码界面；Core 只保证稳定可读短 ID 导出（JSON/CSV）与 Deep Link 路由入口（如 `asterlab://run/<id>/well/A1`），由外部插件消费。
3. **Run 实测反哺新版 Design**：守住已冻结蓝图不可变的前提下，Run 结束后支持一键“用本次实测参数/耗时派生下一版 Design”（而非手工重改）。
4. **任意步骤的现场随手拍证据**：除终点采集矩阵外，Run 任意步骤保留轻量的现场图片/备注挂载入口，作为步骤执行证据。
5. **终态签核与完整归档包**：生命周期补齐 `执行中 → 待总结 → 已签核归档`；归档后 Notebook 锁定只读，支持导出 `PDF 报告 + 原始附件 + 校验清单` 完整归档包。

### 反臃肿三条克制铁律
- 增强能力默认 **可选、折叠、不阻断**；
- 台面组件按当前步骤 **按需现身**（计时器、动态配平表、12 孔采图网格只在该出现的步展开）；
- 外部扩展消费同一份 Core `RecordProjection` 与稳定 ID，不往主工作台塞管理菜单。
