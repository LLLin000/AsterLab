## 2. 不能丢失的产品要求

以下是主人在多个回合中反复确认的要求，优先级高于任何通用设计套路：

1. **在已有 UI 上渐进改进。** 保留已经形成的四步新建设计、现有数据关系和工作台；提出调整时说明对应哪个现有区域、如何改，而不是从空白页重做。
2. **文字精简，但含义必须完整。** 标题和标签尽量短、直接、易懂；不要使用奇怪的复杂术语，也不要为了短而缩到看不懂。页面不要变成全是字。
3. **用视觉减轻理解，不用装饰取代事实。** 组、检测、时间、样本流向、板位等可视关系从同一份结构化数据绘制；图上必须看得出“已知、未知、计划、实际”。
4. **实验设计有创造性，不能被过度校验锁死。** 软件可以检查确定性的格式、引用和计算；不应因为领域规则不完整就阻止研究者保存新颖设计。未知和不确定关系要可见、可追溯，可在草案中保留。
5. **工具与实验设计分开。** 一级“工具”按任务提供铺板、填板、计算、读板、成像、仪器采集等手段。工具使用引用实验上下文，但不另存一份组别/n/科学假设。工具参数聚焦当前目的真正需要的条件。
6. **Protocol 与步骤块复用。** 复用同一种可递归组合、版本化的步骤块；不重复输入同一方法。小参数变化用本次绑定/预设，内容或顺序改变才形成新版本。
7. **人和 Agent 用同一套数据与契约。** 所有工具要写清输入、输出、只读预览/计算/写入/实际执行的区别；Agent 不应生成长篇废话，也不能靠猜测填补必要事实。
8. **研究者保留科学决定。** 软件不擅自决定对照、剂量、时间、n、实验单位、样本兼容性、统计比较或实际执行事实。

## 4. 对象与职责：设计、方法、工具、Run

用户界面要让人看到简单名词，底层语义仍须严格：

| 对象 | 表达内容 | 不应混入 |
|---|---|---|
| 项目 | 相关工作的组织位置 | 单次执行 |
| 实验 | 一个科学问题或目标 | 所有仪器细节 |
| 实验设计版本 | 比较目标、因素/组别、实验单位/n、Assay、时间、计划样本关系 | 实际孔位和实测结果 |
| 检测 Assay | 要测什么、对哪些组、何时测、样本时间关系及方法引用 | 另一套组别或独立 n |
| Protocol / 步骤块 | 怎样操作、哪些步骤和方法参数 | 重新定义科学设计 |
| 工具 | 对当前任务做铺板、填板、计算、仪器采集等；给出预览或结果 | 自行复制一份设计；把建议当实际操作 |
| Run 执行批次 | 冻结引用版本；实际材料、容器/孔位、设备、操作事件和原始数据来源 | 静默重写计划 |

下列关系要始终分开：

- 独立实验单位数 n ≠ 实体样本数 ≠ 孔/管/切片位置数 ≠ 视野或测量次数 ≠ Run 轮数。
- “同一实验单位跨时间重复观察” ≠ “同一份物理样本重复测量” ≠ “每个时间点独立取样”。
- 同一份计划制备材料供多个检测使用 ≠ 多检测共用同一培养单位/同一物理样本。
- 计划布局 ≠ 实际板图；生成排布建议 ≠ 已铺板/已加样。
- 来源关系和时间点关系分别保存；工具不因 Assay 名称猜仪器配置、样本兼容或操作顺序。
- 未知 ≠ 否/零/不适用；未知值不自动填常见值。

完整规范以根目录 CONTEXT.md 为准。若某个现有运行时字段表达不了以上差异，列成契约缺口，先说明最小修改，不要用 UI 假装已经支持。

### 已看到的两个具体问题

1. 总览格当前只有“已选择 / 未选择”，并有提示“未选择不等于已决定不做”。因此用户仍不能在图上区分明确不做与尚未决定。先核对设计数据契约；若其没有显式三态，向用户说明这个最小模型缺口，不能直接给页面画一个假的“不做”。
2. 点击检测标题目前只跳到第 3 步，没有选中该检测或高亮它关联的组；编辑卡也没有“只展开当前检测、其它检测收起”的聚焦模式。这个是适合小步试做的交互候选，修改前要保留每个检测按组的差异和原值。

界面还有连续变化的摘要、样本用法和计数范围。不要凭关系或每组输入数量推导跨时间或跨组的唯一孔位总数；没有明确位置映射就显示逐组数量/待铺板确认。

## 7. 建议的页面层级与文案候选

当前候选方向是“保留四步 + 上方结构总览 + 下方只编辑当前重点”，不是新增主页面，也不是把全部字段塞到一张表里。以下文字是可评审的草案，OMP 需结合实际截图修改：

- 第 1 步：研究目的。保留一句话/导入/复制/手动入口。未有事实留空或待确认；名称可以建议，但不可替代研究问题。
- 第 2 步：实验条件。组卡表达组名、处理条件及独立实验单位/n 的确认状态；孔、读数、容器位数不能被当 n。
- 第 3 步：检测安排。上方设计总览，下面检测卡。字段名采用“检测名称、测量目标、适用组、时间锚点、计划时间、时间点关系、按组设置、方法”这类能直读的短词。
- 第 4 步：样本与检查。编辑跨检测来源、计划共享产物、分样/顺序使用、来源证据和冲突；汇总每项检测的关系并定位到第 3 步编辑，不再提供第二份同字段编辑表。
- 每个阶段均保留明确的“保存草案”。草案可不完整保存；是否能生成板图、执行某个动作或解释结果分别检查，不用一个全局红灯替代所有阶段。

暂定关系图的视觉语法：

- 实线与清晰标签表示已确认关系；虚线/问号 + “待确认”表示未知；明确排除用单独文字状态，不能用空白代替。
- 点击组或检测时高亮上下文并定位唯一编辑处；不靠颜色单独提示。
- 材料流向图只画有来源依据的箭头；来源关系未知时显式标待确认，不能因为没有箭头就暗示无关系。
- 板位图保持精准俯视、对应真实或明确计划映射；2.5D 图仅解释动作，不承担孔位事实。
- 同屏只突出一个主要任务。已知关系可以摘要显示，复杂关系进入有入口、有返回路径的完整编辑。
- 桌面和手机共享数据与状态；手机纵向改排，不用 10px 文字或不易发现的横向滚动解决密度。

请把这些当作候选，重点研究实际页面如何摆放和具体交互，不要把文字直接照抄进 UI。

## 8. 图标与视觉素材的调研结论

本轮查过的官方资料及结论整理在 docs/research/2026-11-04-asterlab-visual-language-research.md：

- Lucide：官方介绍 1600+ SVG，提供 Vanilla JS 包，ISC 许可，强调清楚一致的线条图标。适合作为通用 UI 图标候选。
- Tabler Icons：官方仓库当前列出 6257 个图标，MIT 许可；设计规范 24×24 网格、2px 中置笔画、圆端点/圆角和固定留白。澪交叉审阅后建议把它作为优先候选和唯一通用图标集，统一尺寸/描边/选中态；这是伙伴建议，不是主人最终选型。官方许可页区分开源图标与单独许可的插画、邮件素材，不能混为一谈。
- Phosphor：官方列出 1248 图标、6 种字重、MIT。更易做出有温度的感觉，但需锁定主字重，避免风格混乱。
- 科学关系图和板图应由 AsterLab 自己从数据生成 SVG/HTML，不靠图库里的通用插画。
- 小角色/微型场景可自绘 SVG，但应在主流程清楚后再做。常规界面图标用一个库即可，角色不能表达科学校验通过/失败。
- Linear 官方改版文章适合参考信息层级、导航退后、减少多余分割线与渐进调整。
- xAI 的 Grok Bot 设计文章适合参考统一角色造型和状态表达，及按信息形态选择图文卡片；不能把其聊天/机器人逻辑直接搬到实验设计。
- Opentrons Protocol Designer 适合参考当前操作与相关参数的聚焦编辑，不适合照搬机械臂专用载板模型。
- W3C/GOV.UK 表单资料适合参考清晰标签、纠错路径、复杂条件不应隐藏在简单勾选中。

OMP 应检查当前实际图标资源和画面；若现有资源无法沿用，先以 Tabler 做页面小样，只有仍有明确疑问时才与 Lucide 对照。主人还未确认最终图标集。不要因为许可开放就自动引入依赖。第三方 Rive 的运行时许可和创作/导出条件是不同问题；若建议引入，需要独立核对当前授权、维护与性能成本。

## 9. 实验场景与仪器覆盖

已有真实方案和产品压力测试案例集中在现有研究文档中。本列表用于确保界面研究不是只围绕孔板；它不是“所有生物实验都已验证”，也不是可直接执行的实验 SOP。没有来源的剂量、温度、转速、时间和重复数不可补写。

| 场景 | 需要呈现的关系 | 相关工具/设备类别 | 重点防错 |
|---|---|---|---|
| L929 + GelMA 浸提液，CCK-8 与活死成像 | 处理组、独立培养单位、共享浸提材料、各 Assay 时间与样本用法 | 铺板/填板、培养箱、移液器、酶标仪、荧光显微镜/共聚焦 | 共用浸提材料不等于共用培养孔；D1 事件不等于 D3 已完成；不从孔数推 n |
| SA 铜离子梯度及 OD、CFU、RNA-seq | 因素水平、单位、部分 Assay 覆盖、取样分支和来源冲突 | 梯度/配液计算、分光或读板、稀释/涂板/计数、核酸质控与外送平台 | OD 不自动换 CFU；不要默认所有梯度都送测；单位或体积冲突不可自动选一条 |
| 生物膜多检测 | 培养来源、培养液/附着膜/回收样本、分样、终末去向 | 培养/振荡、读板、涂板计数、成像、共聚焦、SEM 前处理 | 不把不同检测硬串为总流程；OD、CFU、结晶紫和成像指标不能混为一个结果 |
| qPCR + Western + ELISA | 同一来源的 RNA、蛋白、上清分支；对照、原始读数和派生结果 | 定量、离心、PCR/qPCR、凝胶/转膜/成像、洗板/酶标 | 同源不等于同管；技术孔不加 n；缺分析依据时可保留原始采集但不输出伪精确解释 |
| 组织 IHC/IF 与影像 | 来源组织、组织块、固定/冻存分支、切片、视野和图像 | 组织处理/包埋/切片、染色、明场/荧光/共聚焦/扫描 | 固定/冻存不能自动串行；切片/视野不自动成为独立 n |
| 流式分析/分选 | 来源→样本管→面板/控制→采集；分析与分选为不同任务 | 流式仪、计数/离心；必要时后续细胞收集容器 | 不猜设备通道、补偿/解混；分析仪不等于可分选；文件与样本映射明确 |
| 动物纵向与终点取材 | 实验单位、处理分配、笼位/个体关系、纵向测量、终末组织分支 | 行为学/影像设备、活体成像、超声/MRI/微 CT 等按实际方案选择 | 笼或个体是否为单位由研究设计确认；纵向观察不改变 n；终末事实发生后才生成组织材料 |
| 组学与外部平台交接 | 样本来源、制备批、随机化计划、外送回执、实际采集批和原始文件 | 核酸质控、测序/质谱平台或外部服务 | 计划上机顺序不等于实际顺序；送样不等于测序完成；文件不能按名称自动配样 |
| 非孔板边界 | 组织/切片、动物、菌液、植物/区组、无细胞反应等 | 显微、离心、行为平台、环境设备、读板或分析设备 | 不把所有对象塑造成孔板；设备缺失只影响其依赖任务 |

仪器/设备也不能做成全填空。只有当前任务相关的条件出现：酶标仪按吸光/荧光/发光或终点/动力学显露设置；离心机区分目标输出、转子、RCF/rpm 换算；显微成像按定性/定量/3D/活体时间序列显示采集需求；qPCR按相对/绝对定量和化学体系区分字段；流式按分析/分选及设备面板；组学按本地采集/外部交接分开。当前未引用方法/设备时，设计草案不应被仪器参数表阻止。

## 10. OMP 的建议研究步骤

### 第一步：读材料并确认事实

- 从本文件和 docs/research/README.md 起步。
- 核对 README、AGENT_API、CONTEXT；只在需要确认实现时读对应代码函数。
- 查看当前页面实际截图，至少桌面和约 390px 窄屏；若启动程序可能触碰主数据库，使用隔离副本。
- 把结论标成“源码事实 / 浏览器观察 / 产品推断 / 外部依据 / 待确认”，不要混为一谈。

### 第二步：用实际设计任务比较方案

至少用 L929 + GelMA、SA 梯度、生物膜三种结构对照；再用动物纵向或流式/组织/组学中一种验证非孔板边界。所有方案用相同数据：

- 现有版：所有 Assay 编辑项展开；
- 候选版：关系图可选中，当前 Assay 展开，其它 Assay 为摘要；
- 可选对照：检测卡优先 vs 组 × 检测总览，但要检查矩阵是否能清晰表达做/不做/待定。

任务聚焦于读者能否正确找到组覆盖、各 Assay 时间锚点、时间点关系、跨 Assay 样本来源、当前待确认项，以及板位/仪器工具会在何处接手。不要先做整套组件消融；主人已说先把一个大家认可的 UI 方向做清楚，之后再安排消融。

### 第三步：交付一个可以评审的方案

OMP 的研究回传应包含：

1. 当前页面的桌面/手机截图和逐区标注，确认截图属于哪个 commit 和视口。
2. 页面分区和从上到下的顺序，每个区的标题、内容、操作和放置理由；文案要短而不丢科学含义。
3. 现有 UI → 候选 UI 的对照图或低保真线框，明确哪些块保留、压缩、移位或新增。
4. 三个案例逐项走查结果：首次停顿点、误读风险、缺少事实、用户需要补什么；未进行用户测试就写“桌面走查”。
5. 图标方案的实际并排截图、当前依赖是否可复用、许可/版本记录，以及选型理由。
6. 未解决的底层契约缺口；区分必须改数据模型与只需改视图的项目。
7. 一个最小后续实现切片和验收标准。若尚未达到共识，继续研究，不把实现先行。
8. 明确尚未验证的科学兼容性与设备约束；官方资料只能支持具体产品/标准声明。

## 11. 实施前必须共同确认的设计决定

以下问题仍开放，不能以“看起来合理”当成定案：

- 当前矩阵的“未选择”代表什么？是否要在模型中新增明确“不适用/不做”，还是用“待定 + 已选择”以外的别种状态？必须先查现有字段、迁移兼容和 Agent API。
- 关系图上方显示到什么密度、手机下如何避免长图？需要截图比较。
- 点击组/检测后，是只做视觉高亮、同步滚动，还是同时切换编辑卡？要检查键盘/触控无障碍和焦点提示。
- 一个 Assay 收起后，哪些关键事实仍需常驻摘要？至少不能隐藏按组差异、时间锚点/时间点关系状态、来源待确认状态。
- 当前设计卡中哪些字段确实可折叠？“位置数”“容器”“Protocol”不可无依据地全部移到高级区。
- 设计页只引用工具方法还是允许预览工具输出？预览和实际应用必须分开，参数来源要可追溯。
- Lucide、Tabler、Phosphor 在当前暗/亮主题和现有字号下哪个最好？不能只比图标网站截图。
- 是否需要 Lab Buddy？只有当状态理解因此变容易，才值得增加角色；若引入，怎样不干扰专业用户？
- 哪些视觉/动画需要在 reduced-motion 下降级？动态效果不能遮盖选择状态和数值。

如果某项 UX 研究发现用户必须看到一个数据关系，而当前 schema/CLI 表达不了，请回到架构设计阶段补足该关系；不要急着用静态文案补洞。这符合主人的明确要求：界面推演暴露底层怪异时，可以回退讨论。

## 12. 验收线

任何候选 UI 都必须满足：

- 从已有四步流程继续优化；无删除或覆盖用户已有数据。
- 未知、明确不做、不适用三者不混；如果模型不支持，就明确报告契约缺口。
- 逐组不同的样本/时间关系经过收起、编辑其它字段、保存、重开仍不变。
- 不默认全因子组合、不默认每组都有所有检测、不从孔数推 n。
- 改一个 Assay 的样本关系不覆盖其它 Assay；来源共享与物理样本复用分开。
- L929 的 D1 事件不会污染 D3；同一实验单位重复观察不会被改成同一物理样本复测。
- 没有实际孔位映射时不宣称全检测唯一孔位总数；同组数相加不证明跨组无位置重叠。
- 只有依赖某仪器/参数的当前动作会被其缺项阻断；设计草案可继续。
- 计划参数与实际设备/实际读数明确分开；图片/文件和结果能回溯来源。
- 首屏用清晰层级让人知道在看哪个实验、哪一步、正在编辑什么；细节不丢失但不重复堆在一起。
- 390px 视口无关键内容被切断、无必须横向拖动才看见的隐藏关系；最小触控区域、键盘焦点与减少动效同时检查。
- 文案自然简洁，状态不只依赖颜色/表情；图示不能让未知值看起来确定。
- 用户走查前后明确报告证据级别，不把源码推演称为用户测试。
